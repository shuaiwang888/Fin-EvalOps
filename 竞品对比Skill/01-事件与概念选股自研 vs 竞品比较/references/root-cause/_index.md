# 根因归因体系

L1 分类固定不变，用于跨评测聚合统计。L2 是可执行的具体诊断。

## 链路阶段

每个 L1 对应评测链路的一个阶段，用于定位失败发生在哪里：

| L1 | 链路阶段 | 核心问题 | 文件 |
|---|---|---|---|
| `intent` | 理解问题 | 系统是否正确理解了用户要什么？ | [intent.md](intent.md) |
| `evidence` | 检索信息 | 系统找到的信息是否正确、充分、时效对？ | [evidence.md](evidence.md) |
| `tool` | 选择与执行工具 | 系统是否选对了工具、用对了工具？ | [tool.md](tool.md) |
| `reasoning` | 推导投资逻辑 | 事件→传导路径→股票含义的逻辑链是否完整？ | [reasoning.md](reasoning.md) |
| `composition` | 组织答案 | 逻辑可能存在但答案是否呈现出来了？ | [composition.md](composition.md) |

`evidence` 与 `tool` 的关键边界：
- 工具选对了、用对了，但信息本身有问题 → `evidence`
- 工具选错了或用法有误 → `tool`
- 证据存在但没有转译成受益逻辑、排序标准或个股结论 → `reasoning`
- 推理链路中有判断但最终答案表格化、碎片化或主次不清 → `composition`

## 证据规则

每个根因必须绑定证据。

- 使用最终答案、可见推理、工具调用、工具输出和消息结构。
- 如果证据不充分，设置 `confidence: "low"` 并保持宽泛诊断。

## 置信度规则

- `high`（高）：直接被可见答案或链路证据支撑
- `medium`（中）：强烈暗示但不完全明确
- `low`（低）：合理但证据不足；仅在更宽泛分类仍有帮助时使用

## 选择规则

1. 按 raw_score 升序排列所有维度。并列时按权重降序排列，仍并列时按维度名字母序排列。
2. 得分最低的维度映射到最重要的根因。但如果触发的封顶规则上限低于 `absolute_score_pre_cap`，封顶违规维度驱动主要根因——因为它才是真正压低 final_score 的原因。
   注意：在评估根因前，先检查是否有封顶规则可能被触发（参考评分细则中的封顶条件），以便在最低分维度和封顶违规维度之间做出正确选择。
3. 写一句 summary，将 L2 机制与该维度的失败模式融合，解释具体的因果链。
4. 按排名往下扫描，有独立病因（不同 L1，或同一 L1 内不同 L2）的维度追加为额外根因。
5. 返回最多 8 个根因，按重要程度排列。如果所有维度 raw_score ≥ 3 且无封顶触发，属于合格通过，允许返回空数组。否则必须返回至少一个根因——证据不足时设 `confidence: "low"`。
