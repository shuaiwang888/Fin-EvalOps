# 根因归因体系

L1 分类固定不变，用于跨评测聚合统计。L2 是可执行的具体诊断。

## 链路阶段

| L1 | 链路阶段 | 核心问题 | 文件 |
|---|---|---|---|
| `intent` | 理解问题 | 系统是否理解了用户表层问题、隐含财报任务和报告期约束？ | [intent.md](intent.md) |
| `evidence` | 检索信息 | 系统找到的信息是否来自正确报告、公告全文和公司/行业关键证据？ | [evidence.md](evidence.md) |
| `tool` | 选择与执行工具 | 系统是否选对结构化数据、搜索、公告全文和计算工具？ | [tool.md](tool.md) |
| `reasoning` | 财务与业务推理 | 系统是否把数据变化推到真实业务、会计和投资含义？ | [reasoning.md](reasoning.md) |
| `composition` | 组织答案 | 逻辑可能存在但答案是否清楚、重点突出、可信地呈现？ | [composition.md](composition.md) |

`evidence` 与 `tool` 的边界：
- 工具选对了、用对了，但信息本身旧、错、缺、口径不匹配 → `evidence`
- 工具选错、查询词错、未查公告全文、未交叉验证 → `tool`
- 证据存在但没有转译成原因、业务含义或投资判断 → `reasoning`
- 推理链路中有判断但最终答案重点埋没或表达成数据堆砌 → `composition`

## 证据规则

每个根因必须绑定证据。可使用最终答案、可见推理、工具调用、工具输出和消息结构。证据不足时设置 `confidence: "low"` 并保持诊断宽泛。

## 置信度规则

- `high`：直接被最终答案或链路证据支撑
- `medium`：强烈暗示但不完全明确
- `low`：合理但证据不足；仅在宽泛分类仍有帮助时使用

## 选择规则

1. 按 raw_score 升序排列所有活跃维度。并列时按权重降序，再按维度名字母序。
2. 得分最低的维度映射到最重要根因。但如果触发封顶规则上限低于 `absolute_score_pre_cap`，封顶违规维度驱动主要根因。
3. 写一句 summary，将 L2 机制与该维度失败模式融合。
4. 按排名往下扫描，有独立病因（不同 L1，或同一 L1 内不同 L2）的维度追加为额外根因。
5. 返回最多 8 个根因。若所有活跃维度 raw_score >= 60 且无封顶触发，允许返回空数组；否则必须至少一个根因。
