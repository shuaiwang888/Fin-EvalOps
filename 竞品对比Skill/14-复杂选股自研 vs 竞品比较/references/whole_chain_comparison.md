# 整体链路比较层

本文件说明如何基于真实数据结构比较两边整体链路，并把链路差异解释回复杂选股最终答案差异。

## 真实输入形状

### 自研模型常见形状

- `text_answer` 通常有值；
- `answer` 可能包含 markdown、表格或图表；
- `chain` 通常有多个 step；
- 每个 step 可能包含：
  - `plan`
  - `tools` list
- 工具调用常分散在多个 `chain[N].tools[M]` 中。

### 竞品模型常见形状

- `text_answer` 可能为空；
- 最终答案常在 `answer` 中；
- `chain` 可能只有一个 step；
- `plan` 可能为空字符串；
- 工具调用仍然存在，通常位于 `chain[0].tools`，其值是 list。

## 字段读取原则

- 最终答案主锚点：
  - 自研优先 `text_answer`；
  - 竞品若 `text_answer` 为空，则使用 `answer`。
- 可视化答案 `answer` 仅在评估表格、图表、字段和呈现质量时参考。
- `tool_usage` 是评测维度，不是 JSON 字段。
- 工具调用主路径：`chain[N].tools[M]`。
- 顶层 `tools` 即便存在，也可能为 `null`，不能替代 `chain[*].tools[*]`。
- 当 `plan` 为空时，不要臆造不可见推理；直接基于工具行为、工具输出和最终答案做归因。

## 比较什么

整体链路比较不是比较“谁的链路更长”，而是比较谁的链路更能产生高质量复杂选股答案。

1. **意图和条件保留**
   - 是否完整保留显性筛选条件、否定条件、范围条件、排序和输出字段；
   - 是否识别隐性金融语义、业务口径和可用数据边界；
   - 是否避免擅自增删条件、把或关系拆成且关系、把重复强调当成额外条件。

2. **筛选规划**
   - 是否将长问句拆成可执行步骤；
   - 是否区分硬条件、软条件、二次验证和排序；
   - 是否处理先后关系、分层筛选、跨领域交集和无数据兜底；
   - 是否为不可用或需要确认的数据设置边界，而不是强行输出。

3. **工具选择**
   - 结构化行情、财务、资金、技术指标是否用 FinQuery / BackTest；
   - 需要公告、研报、新闻、互动易、合作关系、订单、主线题材、核心技术等非标证据时是否用 Search / AccessingFullText；
   - 需要计算、筛选、合并或公式验证时是否用 CodeInterpreter；
   - 是否避免用宽泛搜索替代结构化取数，或用结构化查询替代非标证据验证。

4. **查询设计**
   - 查询词是否贴合用户任务；
   - 是否补齐指标字段、日期窗口、交易周期、市场范围、板块排除、ST/退市风险、新股限制等约束；
   - 是否聚焦非标条件关键词，如主线题材、合作关系、订单、极端利好、核心技术、护城河；
   - 是否处理工具返回字段、时间戳、低频数据和缺失数据。

5. **证据覆盖与交叉验证**
   - 是否同时覆盖用户条件、候选池、排序字段、边界说明和最终结论；
   - 是否在工具结果之间做交叉核验；
   - 是否处理冲突口径，而不是机械拼接；
   - 是否能从链路证据回溯最终候选股、数值、公式和事实。

6. **证据向答案的转化**
   - 查到的数据是否真正支撑了最终候选池、排序、字段和后续验证建议；
   - 是否存在“链路里查得不错，答案里却没有兑现”的断层；
   - 是否存在“工具很多，但仍然遗漏核心条件或输出不可验证结果”的伪复杂；
   - 图表、表格和字段是否真正帮助用户判断谁符合条件、为什么排序、下一步怎么用。

## 如何解释答案差异

优先写成“链路动作 → 答案结果”的形式：
- 因为自研先拆解了硬条件/软条件/排序字段，再分别取数和搜索验证，所以最终候选池更可核验；
- 因为竞品只做了宽泛搜索、没有结构化验证，所以最终答案无法证明股票满足所有量化条件；
- 因为自研把北向资金流向当作可日频筛选数据，所以候选池建立在已停更口径上；
- 因为竞品虽然 `plan` 不可见，但其 `chain[0].tools` 覆盖了公告与指标字段，所以最终答案在事实边界上更稳；
- 因为某一方工具输出包含正确候选，但最终答案遗漏排序字段，所以链路优势没有兑现。

## 不应做的事

- 不因为自研 chain step 更多，就自动判断其链路更好；
- 不因为竞品 `plan` 为空，就直接把它判成“无推理”；
- 不把 `tool_usage` 误当成 JSON 字段；
- 不只比较工具数量，而忽略这些工具是否真的改善了答案；
- 不用表格长度、图表数量或表达流畅度掩盖条件、口径、候选池、排序或字段错误。
