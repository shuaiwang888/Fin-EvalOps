# `tool_usage` 工具使用合理性（建议权重 5）

此维度在根因诊断阶段（协议步骤 2）评分，而非盲评阶段，因为需要阅读规划链路。

判断规划链路是否选对了工具、用对了工具、用足了工具，并把工具结果转化为金融逻辑。

评分前先阅读 [工具列表](../tool_list/_index.md)。

关注点：
- 市场热点、新闻事件、公告和非结构化产业事实通常需要 Search / AccessingFullText；
- 结构化行情、资金、财务、估值、概念成分、区间涨跌幅通常需要 FinQuery；
- 事件窗口、历史表现或策略验证可用 BackTest；
- 走势预测和多因子诊断可用 Forecast；
- 多条件筛选、排序计算和表格处理可用 CodeInterpreter；
- 工具调用的关键词、时间窗口、股票池、指标和后缀应贴合任务；
- 复杂问题应做必要交叉验证，而非单一工具打天下；
- 工具结果必须服务结论，不能只堆数据。

常见失败模式：
- 用 Search 查 FinQuery 能直接处理的结构化金融数据；
- 用 FinQuery 替代需要新闻、公告或产业事实核验的非结构化证据；
- 短线预测不查最新热点和资金发酵；
- 价值筛选只查低 PE，不查增长、盈利质量和风险；
- 工具很多但最终答案没有吸收关键证据；
- 竞品 `plan` 为空时臆造推理，而不是依据 `chain[0].tools` 做判断。

## 适用性判断

- **始终 relevant**。所有题目均需评估工具使用策略。
