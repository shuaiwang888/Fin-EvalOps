# `tool_usage` 工具使用合理性（权重 10）

此维度在根因诊断阶段（协议步骤 2）评分，而非盲评阶段，因为需要阅读规划链路。

判断规划链路是否选对了工具、用对了工具、用足了工具。

评分前先阅读 [工具列表](../tool_list/_index.md)。

关注点：
- 工具选择正确：结构化金融数据（价格、财务指标、涨停事件）用 FinQuery，策略回测用 BackTest，最新资讯用 StockNews 等
- 分时数据获取：要求精确时间点数据时，是否使用了支持分时查询的工具和参数
- 多步工具编排：多步查询是否按正确顺序执行工具，中间结果是否正确传递到后续工具调用（侧重**工具执行顺序和参数传递**；逻辑条件拆解错误归 `logical_decomposition`）
- 输入格式规范：带正确后缀，FinQuery 时间参数正确，查询条件格式准确
- 遵守工具约束：AnalysisLib 使用时 ActionList 中不能有其他工具且仅在第一步必要时调用
- 工具覆盖充分：复杂的取数计算问题应使用多个工具交叉验证，而非单一工具打天下
- 结果导向：工具评分只评价链路是否支持正确答案，不因固定工具偏好覆盖最终答案质量

常见失败模式：
- 用 Search 查 FinQuery 能直接处理的结构化金融数据（如历史价格、财务指标）
- 未使用 BackTest 工具进行策略回测，而是手动用多步查询拼凑
- 用通用 Search 代替 StockNews 查最新资讯，或代替 NoticeSearch 查公告
- 遗漏工具后缀（如查 StockNews 时未加"新闻"后缀）
- 单次 FinQuery 塞入过多查询条件导致失败，而非合理拆分
- AnalysisLib 与其他工具在同一 ActionList 中混用
- 多步查询中后续步骤未正确引用前序步骤的中间结果

## 适用性判断

- **始终 relevant**。所有题目均需评估工具使用策略；在移除单独耗时维度后，复杂多步工具编排和链路效率判断也统一在本维度体现。
