# 比较协议层

本文件只定义自研 vs 竞品的 pairwise 比较规则；绝对评分标准由本 skill 的 KYC 推荐建议 rubric 体系定义。

## 比较顺序

1. 先确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 先对自研与竞品分别做绝对评分。
3. 再比较双方差异。
4. 最后用链路证据解释差异来源。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更个性化、谁更审慎、谁更有证据和执行价值、谁更值得学习。

## 输出对象的判定规则

### `self_strengths`

仅收录真正成立的我方优势：
- 相对竞品更强；
- 且本身也符合专家标准；
- 且有最终答案、上下文、KYC 信息或链路证据支撑。

常见来源：
- 更准确识别用户的推荐目标、交易决策类型和真实投资处境；
- 更有效使用 KYC 画像、历史上下文、持仓、成本、风险偏好、投资期限或亏损情绪；
- 更清楚地把推荐结论约束在用户风险承受能力和目标期限之内；
- 更合理地选择股票/基金/ETF/资产组合，并解释其配置角色；
- 更充分整合市场、宏观、行业、估值、技术、资金和产品证据；
- 更可执行地给出买卖/持有/加仓/减仓/仓位/触发条件/证伪条件；
- 更稳健地处理风险边界、止损、回撤、极端情景和不确定性；
- 更合理的工具组合被成功转化成答案质量。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键画像、历史上下文、持仓处境、风险偏好或投资目标；
- 只给市场观点、热门标的或模板组合，没有证明“为什么适合这个用户”；
- 产品池选择不合理，或未说明候选产品在组合中的角色；
- 证据不够新、不够深、不够权威，或证据与推荐结论不匹配；
- 可执行建议含糊，缺少仓位、时机、触发条件、止损或备选方案；
- 忽略亏损、套牢、迷茫、焦虑等情绪和风险状态；
- 工具链路虽复杂但没有兑现成更好的结论。

### `competitor_strengths`

只写真正值得学习的地方：
- 竞品在答案中明显更好；
- 或竞品链路中出现了更优的 KYC 获取、证据检索、产品筛选、风险控制或验证策略，并最终改善了答案；
- 不能把“篇幅更长”“措辞更顺”“提示风险更像模板”或“模型名气更大”写成优势。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有真正回答用户的推荐或交易决策问题；
- 都没有使用可见 KYC 数据，或没有说明画像依据不足；
- 都把普通市场分析、热门标的清单或客服式话术当成私人化建议；
- 都缺少关键证据、时效边界或事实核验；
- 都没有给出可执行仓位、条件、风险边界或备选方案；
- 都未处理亏损、套牢、迷茫、急于回本等真实投资处境；
- 都给出过度确定、不可执行或不适合用户画像的行动建议。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终答案的什么地方；
3. 哪段上下文、KYC 或链路证据最能解释这个差异。

推荐优先级：
- `intent_profile_understanding`：先看谁真正理解了用户要什么，以及是否使用画像约束推荐；
- `suitability_personalization` / `risk_boundary_control`：看谁更接近适当性和风控专家标准；
- `decision_actionability`：看谁给出了可执行、可证伪的操作路径；
- `evidence_integration` / `product_universe_fit`：看谁的标的、基金、ETF 或资产选择有证据和配置角色支撑；
- `scenario_emotion_recognition`：看谁更能处理亏损、套牢、迷茫或焦虑等真实处境；
- `recommendation_stability`：看谁对历史建议变化、同类推荐漂移或推荐口径变化有合理解释；
- `composition_credibility`：看谁更可信、审慎、非模板化；
- `tool_usage`：看谁的工具选择、KYC 获取和证据编排更适合任务。

若存在第五类协议允许的临时新增维度，也必须纳入逐维比较，并说明该维度为何对本题成立。

## 结论语义

- `absolute_summary`：先说双方各自按专家标准是否合格。
- `relative_summary`：再说谁相对更好。
- `verdict=self_better`：我方相对更好，且没有被双方共同失败掩盖。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近。
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
