# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更有决策价值、谁更值得学习。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更完整地满足用户资讯问答意图；
- 更严格尊重时间窗口、事实边界和数据口径；
- 更清楚地区分官方事实、市场观点和未核验传闻；
- 更能把多源资讯整合成主线和判断；
- 更准确抓住市场主因、政策含义、产业变化或公司进展；
- 更可执行地映射行业环节、受益标的、风险边界和后续验证点。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉用户显性或隐含约束；
- 事实、日期、统计口径或事件状态不准；
- 证据不够硬、不够新或来源边界不清；
- 资讯整合不收敛，主次不明；
- 核心催化剂或市场主因缺失；
- 投资映射过泛、标的分层不足；
- 表达模板化、不可验证或过度确定。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更直接满足用户意图；
- 事实边界、时间窗口或数据口径更准确；
- 证据表达更权威、更及时、更可验证；
- 多源资讯整合和横向比较更清楚；
- 市场主因、核心信号或传导链条更完整；
- 投资映射、风险边界或观察指标更可执行；
- 非标准资讯的价值和不确定性表达更审慎。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有真正回答用户要问的影响、原因、真假或可持续性；
- 都没有遵守“最新/近期/截至某日/盘中”等时间边界；
- 都缺少关键事实、权威证据或可核验来源；
- 都把资讯、概念标签或行情热度堆在一起，没有形成判断；
- 都漏掉市场主因、核心催化剂或非标准资讯边界；
- 都没有把资讯落到行业、环节、标的、风险和验证点。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_fulfillment`：先看谁真正完成了用户任务；
- `timeliness_fact_boundary`：看谁更尊重时间窗口、事实边界、实体边界和口径；
- `fact_evidence_quality`：看谁的事实和证据更准确、可靠、可核验；
- `information_integration`：看谁更能整合政策、监管、产业、公司事件、市场情绪和数据口径；
- `investment_mapping`：看谁更好地把资讯转化为行业、环节、标的、风险和观察指标；
- `core_signal_extraction`：看谁更准确抓住核心事件、市场主因或判断信号；
- `nonstandard_source_awareness`：看谁更审慎处理传闻、纪要、大 V 文章、官媒截图等来源；
- `credibility_expression`：看谁的结构、语气、边界和可读性更可信。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负（加权总分差 < 8）。
- verdict 只有以上三个值。双方都不达标时用 `absolute_quality_flag=both_poor` 表达，不影响 verdict 的相对判断。
