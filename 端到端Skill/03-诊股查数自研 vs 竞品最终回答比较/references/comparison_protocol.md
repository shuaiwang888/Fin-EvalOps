# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁的数据更准、口径更清楚、计算更可靠、框架更匹配、洞察更有增量、结果更可复核、呈现更清晰。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确识别用户真实诊股/查数意图，而不是只按表层关键词回应；
- 更完整覆盖标的、年份、价格、涨跌幅、资金、分红、客户、行业、宏观指标或全市场筛选条件；
- 更清楚处理日期、交易日、复权、合约、单位、汇率、行业分类、披露进度等口径；
- 更正确完成涨跌幅、差值、总额、比价、跑赢、排序、换算或多标的对比；
- 更贴合市场常用分析框架，例如主力、筹码、增长点、止盈位、商品比价、行业跑赢原因；
- 更能把数据转化为可操作观察点、增量洞察和风险边界；
- 更清楚展示明细、来源、计算过程、表格、图表或可视化。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键数据、标的、年份、字段、行业、客户、分红事件或全市场样本；
- 时间、口径、粒度、单位、复权、合约、汇率或交易日处理不够准确；
- 计算、换算、对比、排序、跑赢判断或条件解析有问题；
- 对主力、筹码、增长点、止盈位、商品比价等问题使用错误或过浅的市场分析框架；
- 数据堆砌但没有洞察、解释、差异、原因或观察点；
- 答案缺少明细、来源、过程或图表解释，导致不可验证。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更直接满足用户意图；
- 数据值、字段、样本、标的、年份或来源更完整准确；
- 日期、交易日、复权、合约、单位、汇率和粒度更可靠；
- 计算、换算、排序、比价、跑赢或累计口径更正确；
- 诊断框架更符合市场常用语义；
- 增量解释、风险边界、验证指标或投资含义更有价值；
- 表格、汇总、图表和结论表达更清楚。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有取到必要数据或样本严重不全；
- 都把时间、交易日、复权、合约、单位、汇率或行业分类口径处理错；
- 都误解用户的诊断框架，例如主力只看单一资金流、筹码只看冷门字段、增长点写成存量业务；
- 都只给数据表，没有结论、差异、原因、风险或观察点；
- 都没有处理用户明确要求的分时精度、全市场条件、历史序列或跨市场比价；
- 都输出不可验证或疑似编造的客户、订单、资金流、研报/调研纪要或统计结果。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_fulfillment`：先看谁真正完成了用户的诊股/查数任务；
- `data_accuracy_coverage`：看谁的数据值、字段、样本、标的、年份和来源更准确完整；
- `time_caliber_precision`：看谁的日期、交易日、复权、单位、合约、汇率和粒度更可靠；
- `calculation_comparison`：看谁的涨跌幅、差值、总额、比价、跑赢、排序或换算更正确；
- `analysis_framework_fit`：看谁更符合市场常用诊断框架；
- `insight_extension`：看谁提供了更有增量的解释、观察点或投资含义；
- `result_verifiability`：看谁能让结果被复现和核验；
- `presentation_visualization`：看谁呈现更清楚，但不得压过正确性。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负（加权总分差 < 8）。
- verdict 只有以上三个值。双方都不达标时用 `absolute_quality_flag=both_poor` 表达，不影响 verdict 的相对判断。
