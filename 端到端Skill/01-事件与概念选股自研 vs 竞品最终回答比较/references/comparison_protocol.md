# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更有决策价值、谁更值得学习。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确地抽象事件驱动；
- 更清楚地区分核心受益、次级受益和弱关联；
- 更可复核的排序标准；
- 更完整的证据闭环；
- 更审慎地标注事实边界、时间边界或业务边界。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键约束；
- 产业链映射不够深；
- 排序标准含糊；
- 证据不够硬；
- 只列概念或数据，未兑现为有效结论。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更直接满足用户意图；
- 排序或分层更清楚；
- 事实边界更准确；
- 证据表达更可验证；
- 逻辑闭环更完整；
- 风险、限制或不确定性表达更审慎。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有真正回答“谁最受益”；
- 都没有给出必要排序；
- 都缺少关键事件时效或硬证据；
- 都把概念标签、行情热度或市值成交额当成投资逻辑本身；
- 都没有区分主营/副业、直接/间接、核心/边缘或上下游。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_fulfillment`：先看谁真正完成了用户任务；
- `event_abstraction`：看谁更准确识别事件、催化剂、政策、供需或主题驱动；
- `industry_mapping`：看谁更准确区分受益链条、实体边界和标的纯度；
- `ranking_judgment`：看谁的排序、分层、优先级标准更清楚；
- `logic_closure`：看谁从事件到标的结论的推理更闭合；
- `timeliness_fact_boundary`：看谁更尊重时间窗口、事实边界和口径；
- `credibility_expression`：看谁更可验证、更审慎、更能帮助用户决策。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好，且没有被双方共同失败掩盖。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负。
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
