# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁拆解更准、覆盖更全、证据更关键、分析闭环更完整、数据口径更严谨、决策输出更可执行、结构更清晰。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确拆出多个子任务、时间窗口、对象范围和输出要求；
- 更完整覆盖关键子任务，并把主任务放在主线位置；
- 更有效整合新闻、公告、行情、产业、政策、财务、资金或案例证据；
- 更清楚形成事实、影响、传导和策略闭环；
- 更严谨处理计算口径、时间窗口、案例真实性、比较口径和盈亏公式；
- 更直接给出策略、择股、布局、调仓、合约、价位、利润测算或触发条件；
- 结构更清楚，能让复杂问题的主结论和子任务答案被快速定位。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键子任务或后半句强约束；
- 覆盖边缘背景很多，但主任务、决策输出或量化比较不足；
- 多源证据并排罗列，没有综合成判断；
- 分析链路停在事实或观点，没有形成传导和策略闭环；
- 时间窗口、计算口径、案例真实性或比较口径有问题；
- 用户要求策略、合约、价位、先例、利润或调仓时，答案没有给可执行输出；
- 结构像资料拼盘，主结论不凝练。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 子任务拆解更完整；
- 主次安排更贴近用户决策；
- 证据组合更贴题、更专业、更能互相印证；
- 分析闭环更清楚；
- 数据、口径、时间窗口或案例更可信；
- 决策输出更直接、更可执行；
- 结构更清晰、更便于复核。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都漏掉用户问题中的关键子任务；
- 都用报告式背景替代复合任务交付；
- 都只堆新闻、公告、数据或表格，没有形成综合判断；
- 都存在关键时间窗口、计算口径、案例真实性或比较口径问题；
- 都没有给用户要求的策略、合约、价位、利润、调仓或择股输出；
- 都没有把事实、影响、传导和策略闭合起来。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_decomposition`：先看谁拆出了全部关键子任务、对象和时间窗口；
- `task_coverage_priority`：看谁覆盖更完整、主次更合理；
- `multi_source_evidence_integration`：看谁把多源证据综合为判断，而不是罗列；
- `analysis_chain_closure`：看谁形成事实、影响、传导、策略闭环；
- `data_logic_rigor`：看谁的计算、时间窗口、口径、案例和推演更可靠；
- `decision_actionability`：看谁给出更直接、更可执行的决策输出；
- `composition_readability`：看谁结构更清晰，但不得压过正确性、覆盖度和可执行性。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负（加权总分差 < 8）。
- verdict 只有以上三个值。双方都不达标时用 `absolute_quality_flag=both_poor` 表达，不影响 verdict 的相对判断。
