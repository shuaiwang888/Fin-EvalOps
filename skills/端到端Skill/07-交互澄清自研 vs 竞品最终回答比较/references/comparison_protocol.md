# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更有咨询闭环、谁更值得学习。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确识别用户真实咨询目标；
- 更清楚地识别必须澄清的变量，并给出可推进的默认方案；
- 更好承接用户补充信息和前轮问题框架；
- 更贴近股民输入习惯地处理错别字、同音、简称或异常代码；
- 更早纠正交易规则、权限、税费、计息和清算中的错误前提；
- 更透明地定义模糊词、指标阈值和时间窗口；
- 更可执行地给出触发条件、仓位节奏、风险边界和后续跟踪动作。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 直接回答了本该澄清的问题；
- 用户补充后没有沿原问题继续推进；
- 标的或语义纠错失败；
- 在错误交易规则前提上继续给建议；
- 口径、时间窗或阈值含糊；
- 具体交易建议缺少风险边界或证据支撑；
- 后续引导只有客套话，没有任务化价值。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更直接满足用户意图；
- 更准确提出澄清问题或默认假设；
- 更好承接多轮信息；
- 更准确识别实体、交易规则或错误前提；
- 更清楚定义口径并说明限制；
- 更可执行、更审慎、更能帮助用户决策；
- 后续引导更贴合当前咨询。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有识别用户真正想解决的投资决策问题；
- 都没有在信息不足时澄清关键变量；
- 都忽略了用户已经补充的信息；
- 都识别错了标的、简称、错别字或异常代码；
- 都没有纠正交易规则或权限错误前提；
- 都没有定义“近期、短线、适中、回调较多”等关键口径；
- 都给出不可验证或不可执行的具体建议；
- 都没有提供有价值的后续监控、提醒或复查动作。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_fulfillment`：先看谁真正回答了用户的真实咨询目标。
- `ambiguity_clarification`：看谁在信息不足、多义或条件模糊时正确澄清或条件化回答。
- `context_continuity`：看谁承接了多轮补充信息和前轮问题框架。
- `entity_resolution`：看谁更准确处理错别字、同音、简称、异常代码和黑话。
- `financial_rule_and_premise`：看谁更准确纠正交易制度、权限、税费、计息、清算和错误前提。
- `assumption_definition`：看谁把模糊条件转成可核验口径。
- `actionability_and_risk_plan`：看谁给出的下一步更可执行、可验证且有风险边界。
- `evidence_grounding`：看谁的事实、规则、行情、公告或数据支撑更充分。
- `guidance_and_retention`：看谁的后续引导更任务化，更能形成咨询闭环。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好，且没有被双方共同失败掩盖。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负。
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
