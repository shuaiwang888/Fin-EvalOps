# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁的数据更准、时间更稳、公式更对、明细更可复核、表达更清晰。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确识别用户的取数、统计、回测或盈亏计算意图；
- 更完整覆盖股票、市场、日期、交易日、样本范围、指标字段和口径；
- 更正确处理节假日、交易日、上市以来、过去 N 年、盘中时点等时间边界；
- 更准确使用收益率、概率、毛利率、费用率、复权收益、组合盈亏等公式；
- 更清楚展示中间数据、样本明细、公式和最终计算过程。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键数据字段、样本范围或筛选条件；
- 时间窗口、交易日、节假日、披露日、盘中时点或复权口径处理不够准确；
- 公式、算术、分子分母、统计口径或单位换算有问题；
- 多步回测没有拆清楚条件发现、信号生成、买卖动作和收益计算；
- 答案缺少中间明细，导致结果不可验证。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更直接满足用户意图；
- 数据覆盖、字段、样本或口径更完整；
- 时间边界和交易日处理更准确；
- 公式、算术和统计口径更可靠；
- 中间明细和计算过程更可复核；
- 表格、汇总和结论表达更清楚。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有取到必要数据或样本严重不全；
- 都把自然日当交易日，或交易日/节假日边界错误；
- 都使用错误公式、错误复权口径、错误分子分母或错误单位；
- 都只给最终结论，没有明细和计算过程；
- 都没有处理用户明确要求的盘中精度、历史完整样本或多步策略条件；
- 都编造或输出无法验证的统计结果。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_fulfillment`：先看谁真正完成了用户的取数计算任务；
- `data_retrieval_accuracy`：看谁的数据覆盖、字段、样本和来源更准确；
- `time_inference`：看谁的日期、交易日、节假日、时间窗口和精度更可靠；
- `calculation_accuracy`：看谁的公式、算术和口径更正确；
- `logical_decomposition`：看谁把复合任务拆成了可执行步骤；
- `result_verifiability`：看谁能让结果被复现和核验；
- `expression_quality`：看谁呈现更清楚，但不得压过正确性。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负（加权总分差 < 8）。
- verdict 只有以上三个值。双方都不达标时用 `absolute_quality_flag=both_poor` 表达，不影响 verdict 的相对判断。
