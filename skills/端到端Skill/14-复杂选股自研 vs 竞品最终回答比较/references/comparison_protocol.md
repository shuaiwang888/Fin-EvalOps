# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的复杂选股 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更可核验、谁更有决策价值、谁更值得学习。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更完整保留长问句中的显性、隐性、否定和字段条件；
- 更准确说明金融指标、交易语义、业务口径和不可用数据边界；
- 更清楚呈现分层筛选、先后依赖、条件交集和二次验证结论；
- 更可复核的候选池、字段展示、无结果解释和排序标准；
- 更审慎地说明限制、风险和后续验证方式。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉或改写关键筛选条件；
- 把或关系拆成且关系，或把重复强调当成多个条件；
- 指标公式、交易日、资金流、龙虎榜、北向、退市风险等口径错误；
- 分层筛选、先后关系、跨领域交集或二次验证在最终回答中不可见或错误；
- 候选池、排序、字段或无结果说明不可用；
- 大量表格或条件复述没有兑现成可用结论。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更直接满足用户意图；
- 条件保留更完整；
- 金融口径或时间边界更准确；
- 候选池和字段更可核验；
- 排序或分层更清楚；
- 风险、限制或不确定性表达更审慎。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都遗漏或改写了核心筛选条件；
- 都没有正确处理金融口径、交易日、分时/K 线、指标公式或数据可用性；
- 都没有输出可核验候选池、必要字段或排序；
- 都只给条件复述、概念名单或漂亮表格，没有形成可用选股结论；
- 都没有说明无结果、低频数据、停更数据或无法精确筛选的边界。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_condition_extraction`：先看谁真正保留了用户任务和全部关键条件；
- `financial_semantics_and_caliber`：看谁更准确处理指标、行情、交易、业务和数据口径；
- `screening_plan_decomposition`：看谁在最终回答中更清楚呈现长问句拆解、分层筛选、二次验证和先后关系；
- `result_correctness_and_coverage`：看谁的候选池、字段和无结果说明更可核验；
- `ranking_and_decision_actionability`：看谁的排序、Top N、候选池优先级和后续使用方式更可执行；
- `data_logic_time_boundary`：看谁的交易日、时间窗口、公式和不可用数据边界更严谨；
- `composition_credibility`：看谁表达更清楚克制，且没有用漂亮呈现掩盖事实或条件错误。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好，且没有被双方共同失败掩盖。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负。
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
