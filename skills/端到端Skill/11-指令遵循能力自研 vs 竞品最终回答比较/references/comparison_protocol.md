# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的主指令解析、维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整执行主指令、谁更准确对齐任务类型、谁更稳地遵守约束、谁更能把必要信息组织成用户要求的答案。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确识别用户主指令，而不是被辅助信息带偏；
- 更好地区分原因、定义、比较、排序、建议等任务类型；
- 更完整覆盖时间、对象、范围、排除项等显式约束；
- 答案焦点更贴近主问，没有用数据表、行情事实或背景材料淹没主答案；
- 更好地把必要信息转化成原因、定义、比较、排序、建议或核实结论。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉用户主指令或把辅助信息当成主问；
- 把原因题答成行情播报，把定义题答成查询结果，把比较题答成分别介绍；
- 忽略时间、对象、范围、排除项等关键约束；
- 答案焦点漂移，用户仍需追问才能得到主答案；
- 必要信息不足，结论缺少原因、定义边界、比较标准或核实依据。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更直接满足用户主指令；
- 更准确对齐原因、定义、比较、排序、建议等任务类型；
- 更完整覆盖时间、对象、范围、排除项等显式约束；
- 答案组织更聚焦，主答案更清楚；
- 必要信息更充分，结论更可验证、更便于用户使用。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有真正回答用户主指令；
- 都把任务类型答错，例如原因题只写上涨事实、定义题只写数据结果；
- 都遗漏关键时间、对象、范围或排除项；
- 都把相关数据堆在答案里，但没有形成用户要求的结论；
- 都用通用模板替代针对本题指令的直接回答。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `explicit_instruction_completion`：先看谁真正完成了用户主指令；
- `task_type_alignment`：看谁更准确对齐原因、定义、比较、排序、建议等任务类型；
- `constraint_coverage`：看谁更完整遵守时间、范围、对象和排除条件；
- `answer_focus`：看谁更围绕主问组织答案，避免数据堆砌和焦点漂移；
- `necessary_information_completeness`：看谁补足了完成主指令所必需的信息、证据、标准或结论。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负（加权总分差 < 8）。
- verdict 只有以上三个值。双方都不达标时用 `absolute_quality_flag=both_poor` 表达，不影响 verdict 的相对判断。
