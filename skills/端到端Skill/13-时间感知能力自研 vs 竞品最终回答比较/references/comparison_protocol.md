# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题和可见请求时间建立双方共享的时间锚点、维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁的日期解析、交易日历判断、as-of 表达、报告期映射和纠错更完整。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确地识别用户的相对时间、市场/品种、自然日/交易日或报告期语义；
- 更正确地把“今天/昨天/下周/去年/年中”解析到请求时间对应的绝对日期、年份或期间；
- 更清楚判断交易日历、节假日、跨市场时区和行情 as-of；
- 更清楚区分报告期、披露日、公告日、股权登记日、除权除息日和派息实施日；
- 在用户前提错误、目标日休市或数据不可得时，先纠错再给替代口径；
- 在最终回答中明确呈现关键时间边界，而不是把日期或 as-of 留给用户猜。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 把时间词当作普通修饰语，未改变数据口径或答案边界；
- 日期、星期、年份、报告期或披露期解析错误；
- 休市日仍解释当日涨跌、开盘走势或盘中变化；
- 使用上一交易日、旧公告或旧财报，却没有说明 as-of 或替代口径；
- 最终回答没有显式告诉用户关键时间事实；
- 请求时间不可见时，没有说明低置信或需要补充。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更好地纠正时间前提或标注 as-of；
- 更准确地表达交易日历、公告/财报日期、行情日期或跨市场时间边界；
- 更清楚地区分报告期、披露期、实施日和替代口径；
- 更审慎地处理未来不可知、数据不可得或时间上下文不明的问题。

不得把篇幅更长、语气更自信、金融分析更多、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有使用请求时间/时区解析相对日期；
- 都把休市日当成有交易日回答；
- 都用旧行情或旧财报冒充今天/最新事实；
- 都把自然语言“去年/年中”私自改成数据库最新可得年份；
- 都没有区分自然日、工作日、交易日、报告期和披露期；
- 都没有在用户前提错误时主动纠错。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `temporal_intent_recognition`：先看谁真正识别了题目中的时间词、市场/品种和时间口径需求；
- `anchor_date_resolution`：看谁把相对时间解析到正确的绝对日期、星期、年份或期间；
- `market_calendar_status`：看谁正确说明目标市场/品种在目标日期是否交易；
- `data_asof_freshness`：看谁表达了数据日期，避免旧数据冒充当前事实；
- `period_disclosure_mapping`：看谁正确处理报告期、披露期、分红流程和替代口径；
- `premise_correction_clarification`：看谁在用户前提错误或模糊时主动纠错；
- `answer_composition_credibility`：看谁在最终答案中清楚呈现时间边界和限制。

## 结论语义

- `absolute_summary`：先说双方各自是否通过时间感知专家标准。
- `relative_summary`：再说谁相对更好。
- `verdict=self_better`：自研相对更好。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负（加权总分差 < 8）。
- verdict 只有以上三个值。双方都不达标时用 `absolute_quality_flag=both_poor` 表达，不影响 verdict 的相对判断。
