# Result-only 比较协议层

本文件只定义自研 vs 竞品最终回答的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 根据用户问题建立双方共享的维度适用性和动态权重。
3. 对自研最终回答与竞品最终回答分别做绝对评分。
4. 逐维比较双方谁更好、差异体现在最终回答哪里。
5. 总结自研最终回答的优点和缺点。
6. 总结竞品最终回答中真正值得学习的优点。
7. 输出双方共同失败点。
8. 给出最终 `verdict`。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更懂用户处境、谁更个性化、谁证据更关键、谁动作更可执行、谁风险边界更稳、谁产品池和推荐原则更清楚。
- 绝对评分只看单边最终回答，相对比较只看双方最终回答的文本差异。

## 输出对象判定规则

### `self_strengths`

仅收录真正成立的自研优势：
- 自研最终回答相对竞品更强；
- 自研最终回答本身达到该维度基本标准；
- 有自研最终回答位置证据。

常见来源：
- 更准确识别用户要推荐、买卖、持有、解套、配置还是产品比较；
- 更好处理用户问题中明示的风险目标、期限、资金规模、持仓成本、亏损或迷茫处境；
- 更清楚地把推荐结论约束在用户风险承受能力和目标期限之内；
- 更合理地选择股票、基金、ETF 或资产组合，并解释其配置角色；
- 更充分整合市场、宏观、行业、估值、技术、资金、产品和同类比较证据；
- 更可执行地给出买卖、持有、加仓、减仓、仓位、触发条件、证伪条件；
- 更稳健地处理止损、回撤、集中暴露、不确定性和高风险主题边界；
- 更有稳定的推荐原则和变化解释。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉用户问题中明示的画像、持仓处境、风险偏好或投资目标；
- 只给市场观点、热门标的或模板组合，没有证明“为什么适合这个用户”；
- 产品池选择不合理，或未说明候选产品在组合中的角色；
- 证据不够新、不够深、不够专业，或证据与推荐结论不匹配；
- 可执行建议含糊，缺少仓位、时机、触发条件、止损或备选方案；
- 忽略亏损、套牢、迷茫、焦虑等情绪和风险状态；
- 推荐口径不稳定且没有解释原因。

### `competitor_strengths`

只写竞品最终回答中值得学习的地方：
- 更准确识别推荐目标、交易决策类型和真实投资处境；
- 更好处理用户问题中的个人化约束或画像不足；
- 产品池、配置角色或核心-卫星结构更合理；
- 证据更关键、更专业、更及时；
- 推荐逻辑更成链条，能解释为什么、怎么配、何时动、何时退出；
- 动作建议更清晰，风险边界更实用；
- 对亏损、迷茫、套牢等处境处理更稳；
- 表达更可信、更审慎、更少模板化。

不得把篇幅更长、措辞更顺、模型名气或任何不可从最终回答文本验证的因素写成竞品优点。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有回答用户真正的推荐、买卖、持有、解套、配置或产品比较问题；
- 都没有处理用户问题中明示的画像、资金、期限、持仓、亏损或情绪处境；
- 都把热门标的清单、市场观点或客服式话术当成私人化建议；
- 都缺少关键证据、同类比较、量化、历史位置或风险收益分析；
- 都没有给出可执行动作和风险边界；
- 都默认推荐窄主题、高波动、集中暴露产品，且没有适配理由；
- 都输出过度确定、不可验证或不适合用户场景的行动建议。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终回答的什么地方；
3. 哪些最终回答证据支撑这个判断。

推荐优先级：
- `intent_profile_understanding`：先看谁真正理解推荐目标和问题中明示的个人化约束；
- `scenario_emotion_recognition`：看谁更好识别亏损、套牢、迷茫等处境并降低错误决策风险；
- `suitability_personalization`：看谁更能解释“为什么适合这个用户”；
- `evidence_integration`：看谁的证据更关键、更专业、更能支撑推荐；
- `decision_actionability`：看谁的动作、条件、仓位和下一步更可执行；
- `risk_boundary_control`：看谁的风险边界、止损止盈、证伪条件更稳；
- `product_universe_fit`：看谁的产品池、配置角色和组合结构更合理；
- `recommendation_stability`：看谁的推荐原则更稳定，变化解释更清楚；
- `composition_credibility`：看谁表达更可信、更审慎，但不得压过适当性、证据和可执行性。

## 结论语义

- `absolute_summary`：先说双方按专家标准各自好不好。
- `relative_summary`：再说双方谁相对更好。
- `verdict=self_better`：自研相对更好。
- `verdict=competitor_better`：竞品相对更好。
- `verdict=tie`：双方接近，差异不足以形成明确胜负（加权总分差 < 8）。
- verdict 只有以上三个值。双方都不达标时用 `absolute_quality_flag=both_poor` 表达，不影响 verdict 的相对判断。
