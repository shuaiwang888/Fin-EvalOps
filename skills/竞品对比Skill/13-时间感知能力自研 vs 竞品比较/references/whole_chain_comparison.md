# 整体链路比较层

本文件说明如何基于真实数据结构比较两边整体链路，并把链路差异解释回最终答案差异。

## 真实输入形状

### 自研模型常见形状

- `text_answer` 通常有值；
- `chain` 通常有多个 step；
- 每个 step 可能包含：
  - `plan`
  - `tools` list
- 工具调用常分散在多个 `chain[N].tools[M]` 中。

### 竞品模型常见形状

- `text_answer` 可能为空；
- 最终答案常在 `answer` 中；
- `chain` 可能只有一个 step；
- `plan` 可能为空字符串；
- 工具调用仍然存在，通常位于 `chain[0].tools`，其值是 list。

## 字段读取原则

- 最终答案主锚点：
  - 自研优先 `text_answer`；
  - 竞品若 `text_answer` 为空，则使用 `answer`。
- 请求时间主锚点：
  - 优先读取显式 `request_time` / `current_date` / `timestamp` 与时区；
  - 若缺失，涉及相对时间的评分必须降低置信度，并在输出中说明证据不足。
- `tool_usage` 是评测维度，不是 JSON 字段。
- 工具调用主路径：`chain[N].tools[M]`。
- 顶层 `tools` 即便存在，也可能为 `null`，不能替代 `chain[*].tools[*]`。
- 当 `plan` 为空时，不要臆造不可见推理；直接基于工具行为、工具输出和最终答案做归因。

## 比较什么

整体链路比较不是比较“谁的链路更长”，而是比较谁的链路更能产生高质量时间感知答案：

1. **工具选择**
   - 节假日、交易所公告、港股/海外休市、最新新闻是否使用 Search；
   - 行情、涨跌幅、财务数据、分红、证券基础信息是否使用 FinQuery；
   - 前 N 个交易日、历史区间和交易日窗口是否使用 BackTest 或等价工具；
   - 未来走势预测是否先确认目标日期可交易，再使用 Forecast；
   - 年报、公告、分红方案和披露文件是否使用 AccessingFullText；
   - 日期/星期推导、批量时间窗口核验是否使用 CodeInterpreter；
   - 截图/图表题是否使用 SearchImage 识别界面日期、as-of 和红框时间锚点。

2. **查询设计**
   - 查询词是否包含目标市场、代码、日期、报告期、时区或节假日；
   - 结构化查询是否输入正确市场、证券代码、自然日/交易日、报告期和统计区间；
   - 是否避免把工作日、自然日或数据库最新可得年份替代用户原始时间口径；
   - 工具无数据时，是否追查“无数据是因为休市/未披露/字段缺失/时间未到”。

3. **证据覆盖与交叉验证**
   - 是否覆盖请求时间、目标日期、目标市场交易状态、数据 as-of 和报告期；
   - 是否在交易日历、行情返回日期、公告/财报披露日期之间做交叉核验；
   - 是否处理冲突口径，而不是机械拼接工具结果。

4. **证据向答案的转化**
   - 查到的日期、休市、as-of、报告期或披露期是否写入最终答案；
   - 是否存在“链路里查得不错，答案里却仍说今天/最新/去年”的断层；
   - 是否存在“工具很多，但仍然按行情模板输出”的伪复杂。

## 如何解释答案差异

优先写成“链路动作 → 答案结果”的形式：
- 因为自研先核验港股休市并读取行情 as-of，所以最终能开头纠正“今天跌了”的错误前提；
- 因为竞品只查了上一交易日行情，没有核验目标日期是否交易，所以最终把旧涨跌解释成今天事实；
- 因为竞品虽然 `plan` 不可见，但其 `chain[0].tools` 包含交易所日历和公告全文交叉验证，所以最终报告期边界更稳；
- 因为自研使用 CodeInterpreter 算对星期但没有查市场日历，所以它只能证明自然日正确，不能证明交易状态正确。

## 不应做的事

- 不因为自研 chain step 更多，就自动判断其链路更好；
- 不因为竞品 `plan` 为空，就直接把它判成“无推理”；
- 不把 `tool_usage` 误当成 JSON 字段；
- 不只比较工具数量，而忽略这些工具是否真的改善了答案；
- 不用后续金融分析的完整度掩盖核心时间前提错误。
