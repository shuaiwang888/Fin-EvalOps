# 时间感知能力自研 vs 竞品比较评测协议

本协议用于比较**同一 `case_id`（同题配对键）下**自研模型与一个竞品模型在时间感知任务中的**整体链路 + 最终回答**。它沿用第 13 类时间感知能力的绝对评分体系，并增加 pairwise 比较协议与链路差异解释方法。

## 协议边界

- **绝对评分**：判断单个模型是否正确理解并使用时间，包括相对日期、交易日历、数据 as-of、财报披露期、报告期和错误时间前提纠错。
- **横向比较**：
  1. 对同题两边分别做绝对评分；
  2. 再比较自研强项、自研弱项和竞品强项；
  3. 最后用两边完整链路解释这些答案差异是怎么产生的。
- 比较对象不是“两个最终答案”这么窄，而是：
  - 同一用户问题；
  - 两边最终回答；
  - 两边可见整体链路，包括 `chain[*].plan`、`chain[*].tools[*]`、工具输入和工具输出。
- 链路的价值在于解释答案差异，不是脱离答案单独评判“工程美学”。

## 适用范围

仅在以下条件同时满足时使用本协议：
- 题目正确性依赖时间推理、时间口径、交易日历、数据时点、报告期或披露期；
- 输入中存在同一 `case_id` 对应的两份记录；
- 两份记录分别代表自研模型与**一个**竞品模型；
- 当前任务目标是回答：
  - 自研模型相比竞品好在哪里；
  - 自研模型相比竞品差在哪里；
  - 竞品模型哪里值得学习。

典型场景包括：
- 今天、昨天、明天、下周一、去年、今年、近 N 日、前 N 个交易日、截至某日等相对时间问题；
- A 股、港股、美股、期货、外汇、贵金属等市场是否开盘、休市、半日市、盘前/盘中/盘后问题；
- 今日行情、最新价格、最近公告、最新财报、旧数据是否冒充当前数据；
- 去年营收、年中分红、季度/年度财报、披露日、报告期和实施日映射；
- 用户问题含错误日期、错误星期、休市却问涨跌、未来不可知或上下文时间不明，需要主动纠错。

不适用于：
- 普通单模型质检；
- 不同问题之间的横向比较；
- 一次同时比较多个竞品模型；
- 完全不涉及时间边界的普通事实问答、纯投资逻辑分析或不依赖当前日期的数据解释；
- 只看最终答案、完全不需要链路归因的轻量 benchmark。

## 输入语义

每次评测至少读取：
- `case_id`：同题配对键（自研与竞品共享）；
- 用户问题；
- 自研模型完整记录；
- 竞品模型完整记录；
- 请求时间、系统时间或会话时间戳 `request_time` / `current_date` / `timestamp`，以及用户所在时区；缺失时必须在评审中标为证据不足。

### 最终答案锚点

- 自研模型：优先使用 `text_answer` 作为最终答案主锚点；
- 竞品模型：若 `text_answer` 为空，则使用 `answer` 作为最终答案主锚点；
- 若编排层已提前生成统一字段，可直接读取归一化后的最终答案，但不得因此改变原始证据指针。

### 真实链路结构

- `tool_usage` 是**评测维度名**，不是输入 JSON 的字段名；
- 真实工具调用从 `chain[N].tools[M]` 读取；
- 顶层 `tools` 字段即便存在，也可能为空，不能把它当成主要链路来源；
- 自研记录通常是多步 `chain`，`plan` 较完整；
- 竞品记录可能只有一个 `chain` step，`plan` 为空，但 `chain[0].tools` 仍包含可用的工具调用证据。

详细规则见：
- [references/comparison_protocol.md](references/comparison_protocol.md)
- [references/whole_chain_comparison.md](references/whole_chain_comparison.md)

## 执行协议

0. **先分析题目，建立共享评测框架**  
   阅读 [references/rubric/_index.md](references/rubric/_index.md)，只依据用户问题、必要上下文和可见请求时间，抽取显式/隐式时间词、市场/品种、数据口径和报告期。对每个维度判断 `relevant` / `supplementary` / `not_applicable`，动态权重总和必须为 100。同一题下，自研与竞品必须使用**同一套**时间锚点、适用性和权重，避免把权重差异误当成模型差异。  
   同时阅读 [references/golden_cases/_index.md](references/golden_cases/_index.md) 与 [references/golden_cases/image_annotation_anchors.md](references/golden_cases/image_annotation_anchors.md)，命中专家案例或同类语义时使用对应 hard checks。

1. **先分别做绝对评分**  
   对自研与竞品分别按本 skill 定义的 8 个维度评分：
   - `temporal_intent_recognition`
   - `anchor_date_resolution`
   - `market_calendar_status`
   - `data_asof_freshness`
   - `period_disclosure_mapping`
   - `premise_correction_clarification`
   - `answer_composition_credibility`
   - `tool_usage`

   除 `tool_usage` 外，先只依据用户问题、必要上下文、请求时间和各自最终答案评分；不得因为另一方更差，就抬高本方绝对分。每个活跃维度的 `raw_score` 必须取六档值：0/20/40/60/80/100。

2. **再分别诊断两边整体链路**  
   阅读 [references/root-cause/_index.md](references/root-cause/_index.md)、[references/tool_list/_index.md](references/tool_list/_index.md) 和 [references/whole_chain_comparison.md](references/whole_chain_comparison.md)。  
   对两边分别检查：
   - 是否识别并解析相对时间、目标市场/品种、自然日/交易日/报告期语义；
   - 是否核验交易日历、节假日、跨市场时区、行情日期、公告日期、财报报告期和披露期；
   - 工具输入是否包含正确市场、代码、日期、报告期、统计区间和 as-of 需求；
   - 工具返回日期是否被正确读取，并转化到最终答案；
   - 当用户时间前提错误、目标日期休市或数据不可得时，最终答案是否主动纠错并说明替代口径。

   当 `plan` 存在时，可结合其判断意图和推理；当 `plan` 为空时，不强行编造“推理文本”归因，优先依据工具行为、证据流和最终答案做判断。

3. **最后做 pairwise 比较**  
   阅读 [references/comparison_protocol.md](references/comparison_protocol.md)。在双方绝对评分完成后，逐维比较：
   - 自研真正做得好的地方；
   - 自研真正落后的地方；
   - 竞品真正值得学习的地方；
   - 双方共同失败点；
   - 哪些链路差异导致了最终答案差异。

   比较时必须坚持：
   - **先绝对、后相对**：双方都差时，先写共同短板，再写谁相对更好；
   - **答案与链路合看**：答案决定质量，链路解释质量是怎么形成的；
   - **证据优先**：每条优势、弱点和学习点都要绑定最终答案或链路证据；
   - **不做多模型聚合**：本协议一次只比较一个竞品，跨竞品总结由后续汇总层完成。

4. **序列化输出**  
   阅读 [references/output-schema_zh.md](references/output-schema_zh.md)。先输出结构化 JSON，再附简短自然语言评审。

## 保守评分

- 自研与竞品使用同一时间锚点、同一维度、同一权重、同一 hard checks；
- 不因为相对胜负而改变绝对评分；
- 不因为链路看起来繁复就自动加分；
- 最终答案决定用户侧质量，链路只用于归因；
- 若链路查对了但最终答案没有说清日期、休市、as-of 或替代口径，不能高分；
- 若双方都没有建立正确时间前提，必须明确输出共同不足，不能把“谁稍微好一点”写成高质量答案。

## 安全护栏

本 skill 的评分安全护栏，尤其包括：
- 时间感知题先判“时间前提是否成立”，再判金融分析是否漂亮；
- 今日/最新类问题必须说明 as-of 时间；旧数据可以作为替代，但不能冒充当前事实；
- “去年/今年/年中”按用户请求时间解析，不能因为最新可得财报只有更早年度就偷偷改年份；
- 下周、下礼拜、前 N 个交易日等必须区分自然日、交易日和节假日顺延；
- 跨市场问题必须按对应市场日历判定，不能混用 A 股、港股、美股、伦敦金、期货或外汇日历；
- 对用户错误前提要纠错。休市、日期/星期不一致、未来不可知或目标报告期未披露时，应先说明限制再给可用替代口径；
- 只要最终答案让用户误以为错误日期、错误年份或旧数据就是当前事实，必须重扣。
