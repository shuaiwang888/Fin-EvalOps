# 比较协议层

本文件只定义自研 vs 竞品的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 先确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 先对自研与竞品分别做绝对评分。
3. 再比较双方差异。
4. 最后用链路证据解释差异来源。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更有决策价值、谁更值得学习。

## 输出对象的判定规则

### `self_strengths`

仅收录真正成立的我方优势：
- 相对竞品更强；
- 且本身也符合专家标准；
- 且有最终答案或链路证据支撑。

常见来源：
- 更准确识别投资场景和真实决策需求；
- 更有效使用上下文、持仓、成本、风险目标或亏损情绪；
- 更关键、更及时、更专业的证据来源；
- 更深入的投资逻辑、因果链和多情景推演；
- 更贴合标的/资产属性的分析方法；
- 更清楚的量化比较、估值位置、历史分位或替代品对比；
- 更可执行的行动建议、触发条件、仓位和风险边界；
- 更合理的工具组合被成功转化成答案质量。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键约束、用户画像、持仓处境或风险偏好；
- 用资讯堆砌、技术指标模板或泛泛财务描述替代核心投资逻辑；
- 证据不够新、不够深、不够权威，或未覆盖关键材料；
- 分析方法与问题、资产类别、投资周期或交易场景错位；
- 可执行建议含糊，缺少条件、仓位、止损、观察点或证伪条件；
- 工具链路虽复杂但没有兑现成更好的结论。

### `competitor_strengths`

只写真正值得学习的地方：
- 竞品在答案中明显更好；
- 或竞品链路中出现了更优的证据获取/验证策略，并最终改善了答案；
- 不能把“篇幅更长”“措辞更顺”或“模型名气更大”写成优势。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有真正回答用户的投资决策问题；
- 都没有抓住核心投资逻辑或当下交易心理；
- 都缺少关键证据、时效边界或事实核验；
- 都把资讯、指标或市场常识拼接成低密度长答案；
- 都未处理可见用户画像、持仓成本、亏损处境或风险目标；
- 都给出过度确定、不可执行或不适合用户处境的行动建议。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终答案的什么地方；
3. 哪段链路证据最能解释这个差异。

推荐优先级：
- `intent_scenario_recognition`：先看谁真正识别了投资场景和用户决策需求；
- `investment_logic_depth` / `method_fit` / `actionability_risk`：看谁更接近专家答案；
- `evidence_source_quality` / `recency_time_boundary`：看谁更可信、更新、更关键；
- `user_profile_suitability` / `scenario_emotion_recognition`：看谁更能处理个人化处境和交易心理；
- `comparison_quantification` / `composition_credibility`：看谁更有量化取舍、表达更可信；
- `tool_usage`：看谁的工具选择和证据编排更适合任务。

若存在运行时新增维度，也必须纳入逐维比较，并说明该维度为何对本题成立。

## 结论语义

- `absolute_summary`：先说双方各自好不好；
- `relative_summary`：再说谁相对更好；
- `verdict=self_better`：我方相对更好，且没有被双方共同失败掩盖；
- `verdict=competitor_better`：竞品相对更好；
- `verdict=tie`：双方接近；
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
