# 整体链路比较层

本文件说明如何基于真实数据结构比较两边整体链路，并把链路差异解释回最终答案差异。

## 真实输入形状

### 自研模型常见形状

- `text_answer` 通常有值；
- `context` 和 `meta.user_investment_goal` 可能包含历史提问、风险偏好、投资目标、投资周期、持仓、成本、风格或偏好；
- `chain` 通常有多个 step；
- 每个 step 可能包含：
  - `plan`
  - `tools` list
- 工具调用常分散在多个 `chain[N].tools[M]` 中。

### 竞品模型常见形状

- `text_answer` 可能为空；
- 最终答案常在 `answer` 中；
- `context` 和 `meta.user_investment_goal` 的可见程度可能与自研不同，但只要输入中可见，就必须纳入评测；
- `chain` 可能只有一个 step；
- `plan` 可能为空字符串；
- 工具调用仍然存在，通常位于 `chain[0].tools`，其值是 list。

## 字段读取原则

- 最终答案主锚点：
  - 自研优先 `text_answer`；
  - 竞品若 `text_answer` 为空，则使用 `answer`。
- KYC 主锚点：
  - 优先读取 `meta.user_investment_goal`；
  - 同时检查 `context`、当前问题自述、画像工具、用户画像存储、历史对话和链路中可见的画像检索结果。
- `tool_usage` 是评测维度，不是 JSON 字段。
- 工具调用主路径：`chain[N].tools[M]`。
- 顶层 `tools` 即便存在，也可能为 `null`，不能替代 `chain[*].tools[*]`。
- 当 `plan` 为空时，不要臆造不可见推理；直接基于工具行为、工具输出、KYC 使用和最终答案做归因。

## 比较什么

整体链路比较不是比较“谁的链路更长”，而是比较谁的链路更能产生高质量 KYC 推荐答案：

1. **KYC 获取与使用**
   - 是否主动读取、调用、检索或引用用户 KYC 数据；
   - 是否识别风险承受能力、投资目标、投资周期、资金约束、持仓、成本、交易经验、偏好和历史亏损处境；
   - 若没有可用画像，是否在答案中说明依据不足，并用分层假设、低风险边界或必要追问处理。

2. **工具选择**
   - 推荐/配置问题是否使用适合的市场、产品、标的、画像或证据工具；
   - 结构化金融数据是否用 FinQuery / BackTest；
   - 需要最新背景、公告或政策时是否使用 Search / AccessingFullText；
   - 需要保存或读取用户画像时是否合理使用画像相关工具。

3. **查询设计**
   - 查询词是否贴合用户任务、标的/产品、投资期限、风险目标和当前市场窗口；
   - 是否补齐市场、宏观、行业、估值、技术、资金、产品费率/跟踪误差、持仓结构等必要证据；
   - 是否避免用过宽泛材料、热门榜单或单一指标替代适当性判断。

4. **证据覆盖与交叉验证**
   - 是否同时覆盖用户画像、产品/标的质量、市场环境、风险收益特征和操作条件；
   - 是否在工具结果之间做交叉核验；
   - 是否处理冲突口径，而不是机械拼接。

5. **证据向答案的转化**
   - 查到的数据是否真正支撑了最终推荐、仓位、期限、触发条件和风险边界；
   - 是否存在“链路里查得不错，答案里却没有兑现”的断层；
   - 是否存在“工具很多，但仍然只输出通用建议或模板组合”的伪复杂。

## 如何解释答案差异

优先写成“链路动作 -> 答案结果”的形式：
- 因为自研读取了用户风险偏好和投资期限，所以最终推荐能区分核心仓位与卫星仓位，并限制高波动标的比例；
- 因为竞品没有使用可见 KYC，只按热门行业给标的，所以最终答案缺少适当性证明；
- 因为竞品虽然 `plan` 不可见，但其 `chain[0].tools` 覆盖了基金持仓、费率、回撤和同类对比，所以最终答案在产品池适配上更稳；
- 因为自研查到了市场证据但没有把证据转化为仓位和证伪条件，所以链路优势没有兑现成用户侧质量。

## 不应做的事

- 不因为自研 chain step 更多，就自动判断其链路更好；
- 不因为竞品 `plan` 为空，就直接把它判成“无推理”；
- 不把 `tool_usage` 误当成 JSON 字段；
- 不只比较工具数量，而忽略这些工具是否真的改善了答案；
- 不因某方风险提示更多就自动判优；模板化风险提示若没有结合用户画像、仓位和具体产品风险，不能替代风控质量；
- 不把“context 中没有 KYC”当成免扣理由；KYC 推荐建议任务本身要求模型主动使用或说明画像依据不足。
