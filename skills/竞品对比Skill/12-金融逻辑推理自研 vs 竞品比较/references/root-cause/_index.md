# 根因归因体系

L1 分类固定不变，用于跨评测聚合统计。L2 是可执行的具体诊断。

## 链路阶段

每个 L1 对应评测链路的一个阶段，用于定位失败发生在哪里：

| L1 | 链路阶段 | 核心问题 | 文件 |
|---|---|---|---|
| `intent` | 理解决策任务 | 系统是否正确理解了用户要做预测、筛选、比较、排序、操作建议还是风险推演？ | [intent.md](intent.md) |
| `evidence` | 收集证据 | 系统找到的信息是否正确、充分、时效对，且覆盖市场驱动和个股属性？ | [evidence.md](evidence.md) |
| `tool` | 工具策略 | 系统是否选对工具、用对工具，并完成必要交叉验证？ | [tool.md](tool.md) |
| `reasoning` | 投资逻辑推导 | 系统是否把证据推导成有决策价值的金融结论？ | [reasoning.md](reasoning.md) |
| `composition` | 组织答案 | 逻辑可能存在但答案是否清楚呈现成用户可用的判断？ | [composition.md](composition.md) |

`evidence` 与 `tool` 的关键边界：
- 工具选对了、用对了，但信息本身不足、过时或口径有问题 → `evidence`
- 工具选错了、参数错误、漏掉应有工具或未交叉验证 → `tool`
- 证据存在但没有转译成市场驱动、投资逻辑、排序标准或风险判断 → `reasoning`
- 推理链路中有判断但最终答案表格化、碎片化或主次不清 → `composition`

## 证据规则

每个根因必须绑定证据。

- 使用最终答案、可见推理、工具调用、工具输出和消息结构。
- 如果证据不充分，设置 `confidence: "low"` 并保持宽泛诊断。

## 置信度规则

- `high`（高）：直接被可见答案或链路证据支撑
- `medium`（中）：强烈暗示但不完全明确
- `low`（低）：合理但证据不足；仅在更宽泛分类仍有帮助时使用

## 选择规则

1. 按 raw_score 升序排列所有维度。并列时按权重降序排列，仍并列时按维度名字母序排列。
2. 得分最低的维度映射到最重要的根因。但如果触发的封顶规则上限低于 `absolute_score_pre_cap`，封顶违规维度驱动主要根因。
3. 写一句 summary，将 L2 机制与该维度的失败模式融合，解释具体的因果链。
4. 按排名往下扫描，有独立病因（不同 L1，或同一 L1 内不同 L2）的维度追加为额外根因。
5. 返回最多 8 个根因，按重要程度排列。如果所有活跃维度 `raw_score >= 60` 且无封顶触发，允许返回空数组。否则必须返回至少一个根因，证据不足时设 `confidence: "low"`。
