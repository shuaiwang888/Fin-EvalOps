# 比较协议层

本文件只定义自研 vs 竞品的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 先确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 先对自研与竞品分别做绝对评分。
3. 再比较双方差异。
4. 最后用链路证据解释差异来源。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更有决策价值、谁更值得学习。

## 输出对象的判定规则

### `self_strengths`

仅收录真正成立的我方优势：
- 相对竞品更强；
- 且本身也符合专家标准；
- 且有最终答案或链路证据支撑。

常见来源：
- 更准确地抽象事件驱动；
- 更清楚地区分核心受益和边缘受益；
- 更可复核的排序标准；
- 更完整的证据闭环；
- 更合理的工具组合被成功转化成答案质量。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键约束；
- 产业链映射不够深；
- 排序标准含糊；
- 证据不够硬；
- 工具链路虽复杂但没有兑现成更好的结论。

### `competitor_strengths`

只写真正值得学习的地方：
- 竞品在答案中明显更好；
- 或竞品链路中出现了更优的证据获取/验证策略，并最终改善了答案；
- 不能把“篇幅更长”“措辞更顺”或“模型名气更大”写成优势。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有真正回答“谁最受益”；
- 都没有给出必要排序；
- 都缺少关键事件时效或硬证据；
- 都把概念标签当成产业逻辑本身。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终答案的什么地方；
3. 哪段链路证据最能解释这个差异。

推荐优先级：
- `intent_fulfillment`：先看谁真正完成了用户任务；
- `event_abstraction` / `industry_mapping` / `ranking_judgment` / `logic_closure`：看谁更接近专家答案；
- `timeliness_fact_boundary` / `credibility_expression`：看谁更可信；
- `tool_usage`：看谁的工具选择和证据编排更适合任务。

## 结论语义

- `absolute_summary`：先说双方各自好不好；
- `relative_summary`：再说谁相对更好；
- `verdict=self_better`：我方相对更好，且没有被双方共同失败掩盖；
- `verdict=competitor_better`：竞品相对更好；
- `verdict=tie`：双方接近；
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
