# `tool_usage` 工具使用合理性（权重 10）

此维度在根因诊断阶段（协议步骤 2）评分，而非盲评阶段，因为需要阅读规划链路。

判断规划链路是否选对了工具、用对了工具、用足了工具。

评分前先阅读 [工具列表](../tool_list/_index.md)。

关注点：
- 工具选择正确：事件背景和时间锚点用 Search，结构化数据用 FinQuery，最新资讯用 Search 加"新闻"后缀，公告用 Search 加"公告"后缀等
- 多条件合并：FinQuery 能一次处理多条件筛选时，应合并为一次调用，而非拆成多次顺序搜索
- 输入格式规范：带正确后缀（如"新闻"、"公告"、"研报"），Search 关键词数量合理，FinQuery 时间参数正确
- 遵守工具约束：CodeInterpreter 用于数据处理和科学计算时，需确保输入为 Python 代码且在沙箱环境中运行
- 工具覆盖充分：复杂的事件驱动问题应使用多个工具交叉验证，而非单一工具打天下
- 非结构化产业事实（主营、供货、客户认证、订单、产能、国际巨头对比）通常需要 Search/AccessingFullText；结构化行情、财务、概念成分、区间涨跌幅用 FinQuery/BackTest 补齐
- 历史事件表现、世界杯/上市前后/事件前后股价等问题，应结合 Search 确定事件窗口，再用 FinQuery/BackTest 计算，不应只查概念成分
- 当 FinQuery 结果与搜索、异动提醒、公告或年报逻辑冲突时，应交叉核验并在最终答案中说明口径，而非拼接冲突结论
- 概念交集/主题交集题不能只用 FinQuery 拉交集名单；需要补查主营业务、业务占比、产品份额、产能、客户和双业务覆盖深度
- 短线事件题应先用 Search 锚定新闻时间、来源和事件内容，再用行情/资金工具验证是否正在发酵

常见失败模式：
- 用 Search 查 FinQuery 能直接处理的结构化金融数据
- 用 FinQuery 查需要 Search 的非结构化事件背景
- 用通用 Search 查最新资讯时未加"新闻"后缀，或查公告时未加"公告"后缀
- 遗漏工具后缀导致查询结果不精准
- 单次 FinQuery 塞入过多主体或指标导致失败，而非合理拆分
- 需要数据处理或计算时未使用 CodeInterpreter
- 多个 FinQuery 可合并的条件未合并为一次调用
- 只用 Search 收集信息，未发挥结构化基本面/行情取数优势
- 只用 FinQuery 列概念池，未补足事件背景、产业事实、非标指标或客户供货证据
- 生成复杂图表但未选择与投资问题直接相关的指标，造成"有图无判断"

## 适用性判断

- **始终 relevant**。所有题目均需评估工具使用策略，包括工具选择、输入格式、多工具编排等。
