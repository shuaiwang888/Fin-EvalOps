# 比较协议层

本文件只定义自研 vs 竞品的 pairwise 比较规则；绝对评分标准由本 skill 的第 14 类复杂选股 rubric 体系定义。

## 比较顺序

1. 先确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 仅依据同一用户问题建立共享维度适用性和动态权重。
3. 先对自研与竞品分别做绝对评分。
4. 再比较双方差异。
5. 最后用链路证据解释差异来源。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更可复核、谁更有决策价值、谁更值得学习。
- 若一方链路更复杂但最终答案没有兑现，不能把链路复杂度写成答案优势。

## 输出对象的判定规则

### `self_strengths`

仅收录真正成立的我方优势：
- 相对竞品更强；
- 且本身也符合专家标准；
- 且有最终答案或链路证据支撑。

常见来源：
- 更完整保留长问句中的显性、隐性、否定和字段条件；
- 更准确理解金融指标、交易语义、业务口径和不可用数据边界；
- 更清楚拆解分层筛选、先后依赖、结构化取数和非标验证；
- 更可复核的候选池、字段展示、无结果解释和排序标准；
- 更合理的工具组合被成功转化成答案质量。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉或改写关键筛选条件；
- 把或关系拆成且关系，或把重复强调当成多个条件；
- 指标公式、交易日、资金流、龙虎榜、北向、退市风险等口径错误；
- 分层筛选、先后关系、跨领域交集或二次验证处理失败；
- 候选池、排序、字段或无结果说明不可用；
- 工具链路虽复杂但没有兑现成更好的结论。

### `competitor_strengths`

只写真正值得学习的地方：
- 竞品在答案中明显更好；
- 或竞品链路中出现了更优的证据获取/验证策略，并最终改善了答案；
- 不能把“篇幅更长”“表格更多”“措辞更顺”或“模型名气更大”写成优势。

常见值得学习点：
- 更准确的条件抽取和问句重写；
- 对不可用、停更、低频数据的边界说明更稳；
- 能把结构化行情/财务数据与公告、研报、新闻、互动易等非标证据结合；
- 排序字段、候选池和后续验证建议更可执行。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都遗漏或改写了核心筛选条件；
- 都把复杂选股当作简单问句或单句查询处理；
- 都没有正确处理金融口径、交易日、分时/K 线、指标公式或数据可用性；
- 都没有输出可核验候选池、必要字段或排序；
- 都用大量图表/表格掩盖核心条件不满足的问题。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终答案的什么地方；
3. 哪段链路证据最能解释这个差异。

推荐优先级：
- `intent_condition_extraction`：先看谁真正保留了用户任务和全部关键条件；
- `financial_semantics_and_caliber`：看谁更准确处理指标、行情、交易、业务和数据口径；
- `screening_plan_decomposition`：看谁更合理拆解长问句、分层筛选、二次验证和先后关系；
- `result_correctness_and_coverage`：看谁的候选池、字段和无结果说明更可核验；
- `ranking_and_decision_actionability`：看谁的排序、Top N、候选池优先级和后续使用方式更可执行；
- `data_logic_time_boundary`：看谁的交易日、时间窗口、公式和不可用数据边界更严谨；
- `composition_credibility`：看谁表达更清楚克制，且没有用漂亮呈现掩盖事实或条件错误；
- `tool_usage`：看谁的工具选择、参数、关键词、交叉验证和工具输出读取更适合任务。

## 结论语义

- `absolute_summary`：先说双方各自按专家标准好不好；
- `relative_summary`：再说谁相对更好；
- `verdict=self_better`：我方相对更好，且没有被双方共同失败掩盖；
- `verdict=competitor_better`：竞品相对更好；
- `verdict=tie`：双方接近；
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
