# 比较协议层

本文件只定义自研 vs 竞品的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 先确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 先对自研与竞品分别做绝对评分。
3. 再比较双方差异。
4. 最后用链路证据解释差异来源。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更准确、谁更深入、谁更有投资决策价值、谁更值得学习。

## 输出对象的判定规则

### `self_strengths`

仅收录真正成立的我方优势：
- 相对竞品更强；
- 且本身也符合专家标准；
- 且有最终答案或链路证据支撑。

常见来源：
- 更准确地理解用户真正问的报告期、指标、口径和结论类型；
- 更完整核验财报数据、公告全文、年报附注或业绩说明会；
- 更准确解释特殊会计事件、非经常性损益、公允价值、套期保值、税务补缴或收入确认；
- 更好地把科目变化连接到业务、行业、价格、订单、成本或产品结构；
- 更审慎地区分短期股价情绪、基本面持续性和估值锚；
- 更合理的工具组合被成功转化成答案质量。

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键公告原文、年报附注或公司披露主因；
- 财务数据、报告期、同比环比、累计/单季、归母/扣非等口径不准；
- 只做表层公式解释，没有回答公司真实发生了什么；
- 业务财务联动不足，无法解释数据变化背后的业务或会计机制；
- 股价影响、持续性或投资含义判断主观，缺少估值锚和观察指标；
- 工具链路虽复杂但没有兑现成更好的最终结论。

### `competitor_strengths`

只写真正值得学习的地方：
- 竞品在答案中明显更准确、更完整或更有决策价值；
- 或竞品链路中出现了更优的公告全文获取、结构化财务查询、计算校验或交叉验证策略，并最终改善了答案；
- 不能把“篇幅更长”“措辞更顺”或“模型名气更大”写成优势。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有命中公告或年报附注中的官方主因；
- 都混淆报告期、数据口径、调整前后数据或单季/累计口径；
- 都用财务公式替代公司特定归因；
- 都缺少业务、行业、价格、订单、成本或会计事件的传导解释；
- 都对股价影响或持续性给出不可验证的主观结论；
- 都缺少必要结论，例如用户问利好利空但答案只罗列数据。

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终答案的什么地方；
3. 哪段链路证据最能解释这个差异。

推荐优先级：
- `intent_understanding`：先看谁真正回答了用户要问的财报问题，是否纠正错误前提；
- `report_data_accuracy`：看谁的报告期、指标、金额、同比环比和会计口径更准确；
- `primary_evidence_quality`：看谁更好使用公告全文、年报附注、季报说明、官网公告、问询函或业绩说明会；
- `causal_attribution_depth`：看谁更准确解释业绩变化、科目差异或特殊事件的主因；
- `business_financial_linkage`：看谁更好完成业务事实到财务指标的传导；
- `forward_investment_judgment`：看谁更审慎、有证据地判断持续性、利好利空、估值和股价影响；
- `composition_credibility`：看谁表达更清楚、可信、重点突出；
- `tool_usage`：看谁的工具选择、查询设计、全文阅读、计算校验和交叉验证更适合任务。

## 结论语义

- `absolute_summary`：先说双方各自按专家标准好不好；
- `relative_summary`：再说谁相对更好；
- `verdict=self_better`：我方相对更好，且没有被双方共同失败掩盖；
- `verdict=competitor_better`：竞品相对更好；
- `verdict=tie`：双方接近；
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
