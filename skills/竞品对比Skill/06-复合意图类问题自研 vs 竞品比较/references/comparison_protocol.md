# 比较协议层

本文件只定义自研 vs 竞品的 pairwise 比较规则；绝对评分标准由本 skill 的 rubric 体系定义。

## 比较顺序

1. 先确认同题：`case_id` 配对到同一问题，问题文本语义一致。
2. 先抽取复合任务框架：子任务、主次关系、证据需求、时间窗口、数据口径、决策输出要求。
3. 对自研与竞品分别做绝对评分。
4. 再比较双方差异。
5. 最后用链路证据解释差异来源。

## 先绝对、后相对

- 不得因为竞品更差，就把自研的绝对短板写成优势。
- 不得因为自研更差，就忽略竞品也没有达到专家标准。
- 若双方都未通过 hard checks，先写 `shared_failures`，再写相对优劣。
- 若双方都合格，再比较谁更完整、谁更严谨、谁更可执行、谁更值得学习。
- 复合意图题不能只看“覆盖点更多”。覆盖更多但主任务错、证据错、结论不可执行，仍然不是高质量答案。

## 输出对象的判定规则

### `self_strengths`

仅收录真正成立的我方优势：
- 相对竞品更强；
- 且本身也符合专家标准；
- 且有最终答案或链路证据支撑。

常见来源：
- 更准确地拆解复合任务；
- 更完整地覆盖关键子任务并处理主次关系；
- 更有效地整合行情、新闻、公告、产业、政策、财务、资金或案例证据；
- 更严谨地处理时间窗口、数据口径、计算和案例真实性；
- 更完整地形成事实、影响、传导、策略闭环；
- 更可执行的策略、择股、布局、调仓或交易方案；
- 更合理的工具组合被成功转化成答案质量；

### `self_weaknesses`

收录自研相对竞品或相对专家标准的真实不足：
- 漏掉关键子任务；
- 子任务主次错位，次要信息挤占核心判断；
- 多源证据只是罗列，没有综合；
- 时间窗口、数据口径、计算、案例真实性存在问题；
- 事实到影响、传导、策略没有闭环；
- 操作建议、触发条件、风险边界不够明确；
- 工具链路虽复杂但没有兑现成更好的结论；

### `competitor_strengths`

只写真正值得学习的地方：
- 竞品在答案中明显更好；
- 或竞品链路中出现了更优的证据获取、验证、计算或提炼策略，并最终改善了答案；
- 不能把“篇幅更长”“措辞更顺”“表格更多”或“模型名气更大”写成优势。

### `shared_failures`

双方都没达到专家标准时必须填写。典型情况：
- 都没有正确拆解复合任务；
- 都漏掉用户后半句的强子任务；
- 都只写背景材料，没有综合判断；
- 都缺少关键时间窗口、数据口径或案例真实性核验；
- 都没有把事实、影响、传导和策略串成闭环；
- 都没有给出用户要求的决策输出；

## 逐维比较

每个活跃维度都要回答三件事：
1. 谁更强 / 是否打平；
2. 差异体现在最终答案的什么地方；
3. 哪段链路证据最能解释这个差异。

推荐优先级：
- `intent_decomposition`：先看谁真正识别了所有显性和隐性子任务；
- `task_coverage_priority`：看谁覆盖了关键子任务，并正确处理主次；
- `multi_source_evidence_integration`：看谁把多源材料整合成判断，而不是资料并列；
- `analysis_chain_closure`：看谁完成事实、影响、传导、策略闭环；
- `data_logic_rigor`：看谁的时间窗口、数据口径、计算和案例更可靠；
- `decision_actionability`：看谁的输出更能指导执行；
- `composition_readability`：看谁的结构更清楚、重点更突出；
- `tool_usage`：看谁的工具选择、查询设计、交叉验证更适合任务；

## 结论语义

- `absolute_summary`：先说双方各自好不好；
- `relative_summary`：再说谁相对更好；
- `verdict=self_better`：我方相对更好，且没有被双方共同失败掩盖；
- `verdict=competitor_better`：竞品相对更好；
- `verdict=tie`：双方接近；
- `verdict=both_poor`：双方都明显不达标，即便一方分数略高，也优先使用该结论。
