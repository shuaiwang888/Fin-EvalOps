# 06-复合意图类问题 Skill

> 自研模型「一句话包含多个子任务、跨多源信息整合、复杂投研推理」类问题的评测协议。

---

## 一、Skill 定位与目标

**核心使命**：评测自研模型在**复合意图或复杂投研推理**任务上的表现。

**关键定位**：

- **主锚点**：`text_answer`
- **辅助证据**：`chain` + 耗时证据
- **设计哲学**：**复合意图的第一性目标是识别所有关键子任务，按主次组织答案，并把事实、影响、传导和策略形成闭环**。
- 评测重点不是"写得多不多"，而是"**拆得准、答得全、证据能支撑、结论能落地**"。

## 三、适用范围

**适用**：

- 一句话包含多个子任务、多个时间窗口、多个资产/公司/行业或多个输出要求
- 复杂问句，字数较长，包含"现状/未来/影响/传导/策略/标的/估值/利润/案例/怎么做"等多层要求
- 深度调研、行业竞争格局、产业链映射、事件影响评估、热点板块归纳、复杂交易方案
- 需要把行情、新闻、公告、产业、政策、财务、资金、舆情等多源信息串成统一投资结论

**不适用**：

- 纯单一意图的行情查询
- 单步取数计算
- 普通 KYC 推荐
- 简单事件概念选股
- 客服问题

**边界判定**：既有单一领域特征又包含多个强子任务时，以"**是否需要拆解、整合、推演并输出决策闭环**"为准。

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | **拆解复合任务** + 抽子任务 + 抽维度 + 动态权重 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评最终答案 | 各维度 `raw_score` + `evidence` |
| **步骤 2** | 链路诊断 + 根因 + `tool_usage` 评分 | `root_causes` |
| **步骤 3** | 应用封顶规则 | `caps` 数组 |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

**关键步骤强调**：

- **步骤 0**：从 `question` 抽取**子任务清单、主次关系、证据需求、时间窗口、量化要求、决策输出要求和效率要求**
- **步骤 2**：用 `chain.plan` 判断**是否正确拆解子任务、排序主次和编排信息源**；用 `chain.tools[*]` 判断**工具选择、时间窗口、证据质量、数据口径**
- 题目命中 10 个专家样例、或输入里包含问财/豆包截图 OCR/人工批注/竞品对比摘要时，必须读取 `golden_cases/image_output_anchors.md`

## 五、9 个评分维度

| 维度 | 建议权重 | 适用性 | 核心关注 |
|---|---:|---|---|
| `intent_decomposition` 意图拆解 | 16 | **始终 relevant** | 子任务是否被正确拆分 |
| `task_coverage_priority` 子任务覆盖与主次 | 14 | **始终 relevant** | 是否答全、有无主次 |
| `multi_source_evidence_integration` 多源证据整合 | 14 | relevant | 行情/新闻/公告/产业/政策/财务/资金/舆情 |
| `analysis_chain_closure` 分析链路闭环 | 16 | **始终 relevant** | 事实→影响→传导→策略的闭环 |
| `data_logic_rigor` 数据与逻辑严谨性 | 14 | relevant | 计算/回撤/估值/利润/案例/时间窗口/量化对比 |
| `decision_actionability` 决策表达与可执行性 | 10 | relevant | 策略/择股/布局/调仓/合约/价位/操作框架 |
| `composition_readability` 结构与可读性 | 5 | **始终 supplementary** | 复杂题的可读性 |
| `tool_usage` 工具使用合理性 | 7 | **始终 relevant**（链路诊断） | |
| `latency_efficiency` 响应效率 | 4 | supplementary | 有耗时证据时评分 |

## 六、7 个封顶规则（cap rules）

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `missed_major_subtask` 漏答主要子任务 | **65** | 强子任务未答 |
| `data_or_case_unreliable` 数据/案例失实 | **55** | 数据错/案例假 |
| `calculation_or_time_window_error` 计算/时间窗口错 | **55** | 月内最大回撤/事件后交易日/48h/7d 窗口错 |
| `information_pile_without_synthesis` 资料拼盘无综合 | **60** | 三段素材拼接无结论 |
| `missing_required_decision_output` 缺必要决策输出 | **65** | 给热点/策略/合约但无触发条件/盈亏公式/风险边界 |
| `wrong_or_shallow_evidence_mix` 证据类型错/过浅 | **60** | 应该查研报但查了新闻 |
| `severe_latency_without_quality_gain` 严重耗时无质量收益 | **75** | 耗时极长但结果没明显更好 |

## 七、8 个 L1 根因归因体系

| L1 | 核心问题 |
|---|---|
| `intent` 理解问题 | 意图理解 |
| `coverage` **任务覆盖** | 子任务是否答全 |
| `evidence` 检索证据 | 证据质量、深度、覆盖 |
| `tool` 选择与执行工具 | 工具选择、参数、口径 |
| `data_logic` **数据/逻辑严谨性** | 数据和逻辑的严谨性 |
| `reasoning` 推理闭环 | 分析链路闭环 |
| `composition` 组织答案 | 表达可读性 |
| `latency` **响应效率** | 耗时效率问题 |

`coverage`、`data_logic`、`latency` 是本 skill 独有的 L1 阶段。

---

## 八、关键评分原则（保守评分 6 条）

1. **最终答案决定用户侧质量**，链路只用于归因
2. **不要把"回答很长/表格很多/工具调用很多"自动视为高质量**
3. **复合意图的第一性目标**：识别所有关键子任务，按主次组织答案，形成闭环
4. **截图型或 OCR 型输入中若出现人工批注**（如"口径存在偏差""数据错误""案例失实""操作建议模糊"），必须把批注作为高优先级专家信号
5. **严惩漏答关键子任务、用资料拼盘替代综合结论、数据口径错误、案例失实、时间窗口错配、结论没有操作价值**
6. **对复杂任务要同时记录效率**。若耗时极长但结果没有明显质量收益，应暴露 `latency_efficiency` 问题

---

## 九、10 个专家案例 + image_output_anchors

- 10 个专家案例 hard checks
- `image_output_anchors.md` 是从**问财/豆包截图和人工批注**提取的好答案、差答案、封顶和归因锚点

**特别用于校准以下高频误判**：

- 把月内最大回撤、事件后交易日、48 小时/7 天窗口等关键口径算错
- 用报告式结构和大量表格掩盖数据、案例或资金流错误
- 回答覆盖了背景，却漏掉用户后半句的强子任务
- 给出热点、策略、合约和价位，但没有可执行触发条件、盈亏公式或风险边界
- 耗时显著超过竞品，却没有换来更可靠、更完整或更可执行的结果

## 十一、与其他 skill 的边界

- ❌ **不适用**：纯单一意图的行情查询、单步取数计算、普通 KYC 推荐、简单事件概念选股、客服问题
- 与 **01-事件与概念选股**：本 skill 强调多子任务拆解；01 强调排序选股
- 与 **05-KYC 推荐建议**：本 skill 强多子任务；05 强 KYC 适配
- 与 **13-时间感知**：本 skill 偏任务覆盖；13 偏时间锚点

## 快速上手 Checklist

1. **步骤 0** **拆解复合任务**（识别所有子任务、主次、证据需求），再分配权重
2. **步骤 1** 检查 `task_coverage_priority`（14 分）和 `analysis_chain_closure`（16 分）两大权重
3. **步骤 2** 检查 `chain.plan` 是否正确拆解子任务、排序主次
4. **步骤 3** 检查 7 个封顶（**特别注意 `missed_major_subtask` 和 `missing_required_decision_output`**）
5. **步骤 4** 输出 JSON

**核心方法论**：「**拆得准 + 答得全 + 闭环落地**才是好答案；资料堆砌≠综合。」
