# Round 1 分析输出格式

Round 1 的输出为**自然语言分析报告**，不是 JSON。按以下小节组织内容。

## 1. 维度适用性判断

逐个维度说明适用性级别及其理由：

- **relevant**：该维度对本题目的评测至关重要，必须重点考察
- **supplementary**：该维度有参考价值但不是核心，权重较低（≤5）
- **not_applicable**：该维度与本题完全无关，不参与评分

格式示例：
```
- temporal_intent_recognition: relevant — 用户问题包含明确的时间表达，需识别时间意图
- market_calendar_status: relevant — 需判断目标市场在目标日期是否交易
- period_disclosure_mapping: not_applicable — 本题不涉及财报或分红报告期
```

## 2. 权重分配方案

为所有活跃维度（relevant + supplementary）分配整数权重，总和必须为 100。

用表格列出每个活跃维度的分配权重和理由：

```
| 维度 | 权重 | 理由 |
|------|------|------|
| market_calendar_status | 25 | 交易日历判断是本题核心前提 |
| data_asof_freshness | 20 | 需核验数据时点是否匹配用户要求 |
| ... | ... | ... |
```

supplementary 维度权重不超过 5。

## 3. 关键证据摘要

从题目、答案、规划链路（chain）中观察到的关键信号。包括：
- 用户问题的时间锚点、市场标的和交易状态
- 答案中表现突出的亮点
- 答案中明显的缺陷或遗漏（时间错误、旧数据、未纠错）
- 工具调用链路中的关键节点（交易日历查询、行情日期核验）

## 4. 致命缺陷候选

初步识别可能触发的 cap label 项，格式：

```
- [label_tag]: 触发原因简述
```

如果未观察到致命缺陷，写明"未观察到致命缺陷"。
