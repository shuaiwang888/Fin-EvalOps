# 时间感知能力评测协议

用稳定协议评测我方模型是否正确理解并使用时间。以用户问题和最终答案 `text_answer` 为评分主锚点，以完整链路数据用于工具评分、时间锚点诊断和根因归因。

## 适用范围

仅在用户问题的正确性依赖时间推理、时间口径或交易日历时使用，包括：
- 相对时间：今天、昨天、明天、下周一、下礼拜二、去年、今年、近 N 日、前 N 个交易日、年中、季末、截至某日
- 交易日历：A 股、港股、美股、期货、外汇、贵金属等市场是否开盘、节假日休市、半日市、盘前/盘中/盘后、跨时区日期
- 日期推理：自然日与交易日、周几、节假日顺延、未来日期、历史日期、日期与星期不一致
- 数据时点：今日行情、最新价格、最近公告、最新财报、年报/季报披露期、数据 as-of 时间、旧数据冒充当日数据
- 时间前提纠错：用户问题含错误日期、错误开盘前提、错误年份或模糊时间时，答案是否主动澄清

不适用于完全不涉及时间边界的普通事实问答、纯投资逻辑分析或不依赖当前日期的数据解释；若问题同时属于诊股查数、分析评价或事件选股，但错误主要来自时间锚点/交易日历/数据时点，本 skill 应优先或并行使用。

## 期望输入

每次评测获取：
- 用户问题 `question`
- 我方最终答案，优先使用 `text_answer`
- 完整对话上下文 `context`
- 完整规划链路 `chain`，包括 `plan`、工具调用、工具输入和工具输出
- 可用工具清单 `tools`
- 请求时间、系统时间或会话时间戳 `request_time` / `current_date` / `timestamp`，以及用户所在时区；缺失时必须在评审中标为证据不足
- 可选人工复核反馈、线上维度统计或新增失败样本 `online_dimension_signals`

## 执行协议

0. **抽取时间锚点并分配动态权重**  
   阅读 [references/rubric/_index.md](references/rubric/_index.md) 和 [references/golden_cases/_index.md](references/golden_cases/_index.md)。先只看 `question`、必要 `context` 和可见请求时间，抽取：
   - 显式日期、相对日期、周期词、交易日词、市场/品种、数据口径词
   - 评测所需的标准答案锚点：自然日期、星期、交易状态、财报期间、数据 as-of 边界
   对每个维度判断 `relevant` / `supplementary` / `not_applicable`，动态权重总和必须为 100。命中专家案例或同类语义时，必须使用对应 hard checks；未命中具体案例时，也要使用跨案例判分锚点。

1. **盲评最终答案**  
   以 `text_answer` 为主锚点评分，不因为隐藏链路更好而给最终答案加分。检查答案是否把关键日期、市场状态、数据时点和不确定性直接告诉用户。对所有活跃维度输出 `raw_score` 和 `evidence`；不要计算加权分、总分或最终分数。`tool_usage` 例外，在步骤 2 评分。

2. **链路诊断和根因归因**  
   阅读 [references/root-cause/_index.md](references/root-cause/_index.md)，再阅读 [references/tool_list/_index.md](references/tool_list/_index.md)。用 `chain.plan` 判断是否正确识别时间锚点、是否决定核验交易日历和数据 as-of；用 `chain.tools[*].input/output` 判断是否查了正确日期、市场、证券代码、报告期和工具返回日期。此时评分 `tool_usage`。根因必须绑定具体证据。

3. **应用封顶规则**  
   按需读取 [references/rubric/](references/rubric/_index.md) 中的封顶规则。封顶规则限制最终分，不替代维度评分。多个封顶同时触发时取最低上限。

4. **序列化输出**  
   阅读 [references/output-schema_zh.md](references/output-schema_zh.md)。先输出结构化 JSON，再附简短自然语言评审。

## 保守评分

- 时间感知题先判“时间前提是否成立”，再判金融分析是否漂亮。若市场当天休市、日期不存在交易、用户的星期/日期前提错误，直接套行情模板是严重错误。
- 今日/最新类问题必须说明 as-of 时间；用上一交易日、旧行情或历史财报回答时，必须显式说明原因和限制。
- “去年/今年/年中”按用户请求时间解析，不得因为最新可得财报只有更早年度就偷偷改年份；若目标报告期未披露，应先说明未披露，再给最新可得数据作为替代。
- 下周、下礼拜、前 N 个交易日等必须区分自然日、交易日和节假日顺延。市场休市不等于把问题自动平移到下一个交易日，除非用户明确要求。
- 跨市场问题必须按对应市场日历判定；A 股、港股、美股、伦敦金、期货的休市和时区不能混用。
- 对用户错误前提要纠错。高质量答案会先说“今天该市场无交易/该日期不是开盘日/你说的日期与星期不一致”，再给可用替代口径。
- 只要最终答案让用户误以为错误日期、错误年份或旧数据就是当前事实，必须重扣；链路里查对了但最终没说清，也不能高分。
