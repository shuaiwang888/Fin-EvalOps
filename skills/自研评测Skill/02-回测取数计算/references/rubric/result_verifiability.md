# `result_verifiability` 结果可验证性（权重 10）

判断答案是否提供了足够的明细数据，让用户能够独立验证结论。

关注点：
- 逐行明细：统计概率类查询是否列出了每个数据点（如每个涨停日期、每次次日涨跌幅），而非仅输出最终概率
- 计算过程：是否展示了公式代入过程和中间计算结果
- 数据来源标注：关键数据（如买入价、卖出价、日期）是否有明确标注

常见失败模式：
- 仅输出宏观结论（如"连板天数一般为2天"）而无明细数据支撑，用户无法验证
- 统计概率缺少逐事件明细：只给出"概率=60%"但不列出被统计的每个事件
- 计算过程不透明：直接给出盈亏金额但不展示买入价、卖出价、股数的代入过程

> **边界说明**：本维度关注计算结果是否可验证（正确性层面），即用户能否根据提供的明细和过程独立复现结论。展示是否清晰、排版是否美观属于 `expression_quality`（可读性层面）。

## 适用性判断

- **relevant**: 题目涉及统计概率、历史回测、长期统计等需要逐条明细支撑的查询
- **supplementary**: 题目为单次取数/计算，明细有助于验证但非核心要求
