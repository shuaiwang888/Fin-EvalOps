# 02-回测取数计算 Skill

> 自研模型「回测取数计算」类问题的端到端评测协议，沉淀诊股查数、条件选股计算、历史统计、事件回测、组合盈亏等场景的评分细则与根因归因体系。

---

## 一、Skill 定位与目标

**核心使命**：用稳定协议评测自研模型在「回测取数计算」类问题上的**最终答案质量**和**完整链路质量**。

**关键定位**：

- **主锚点**：`text_answer`（最终答案）—— 盲评打分
- **辅助证据**：`chain`（完整规划链路）—— 根因归因
- **设计哲学**：回测取数题的核心是**取数准确 + 时间推理正确 + 公式正确 + 多步拆解完整**，惩罚数据虚构，单独惩罚日内精度缺失。

## 三、适用范围

**适用**：

- 诊股查数：历史价格、财务指标、涨停事件
- 条件选股计算：按条件筛选 + 区间涨跌幅、概率
- 历史统计：过去 N 年某行业/月份的上涨概率
- 财务指标提取与对比：营收/成本/费用 → 衍生指标 + 历史对比
- 组合盈亏计算：给定买入操作 → 到期盈亏
- 事件回测：涨停后次日表现、年报发布后涨跌幅、分红再投资
- 多步条件回测：连续 N 日下跌后买入某指数的收益率

**不适用**：事件/概念驱动选股、投资建议、市场评论、纯行情查询。

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | 适用性判断 + 动态权重 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评（不看链路） | 各维度 `raw_score` + `evidence` |
| **步骤 2** | 链路诊断 + 根因 + `tool_usage` 评分 | `root_causes` |
| **步骤 3** | 应用封顶规则 | `caps` 数组 |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

**特殊点**：`latency_efficiency` 在有耗时证据时评分；无证据给中性分并说明。

## 六、6 个封顶规则（cap rules）

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `data_fabrication` 数据虚构 | **35** | 编造统计数据/伪造计算结果 |
| `time_inference_error` 时间推理错误 | **45** | 交易日/自然日/节假日错误 |
| `calculation_logic_error` 计算逻辑错误 | **50** | 公式/算术/复权/财务指标方法错 |
| `intraday_precision_missing` 日内精度缺失 | **55** | 用户要求某时某分/盘中精度但用日线替代 |
| `missing_required_data` 必要数据缺失 | **60** | 关键数据未提供且未补足 |
| `unverifiable_result` 结果不可验证 | **65** | 结论无明细、无中间值 |

|---|---|---:|

## 八、12 个专家案例（golden cases）

沉淀了 12 个专家案例 hard checks，覆盖：

- 历史涨跌幅计算（带前复权/分红再投资）
- 涨停后次日表现统计
- 年报发布后 N 日涨跌幅
- 连续 N 日下跌后买入某指数的收益率
- 区间盈亏计算（含税费）
- 跨市场交易日对齐
- 多步复合回测

**核心警示**：

- 严肃对待时间推理：节前 N 日/上市以来/过去 X 年/某年某月某日某时某分 → 精确交易日推算
- 严肃对待数据完整性：统计概率类需要足够历史样本量
- 严肃对待计算公式：毛利率/期间费用率/前复权价等
- 严肃对待多步拆解：复合条件查询不能直接跳过
- **惩罚数据虚构** —— 编造金融统计数据对投资者风险远大于数据不完整

---

## 九、关键评分原则（安全护栏 7 条）

1. **严肃对待时间推理** —— 节前 N 日、上市以来、过去 X 年、具体日期 → 精确交易日推算
2. **严肃对待数据完整性** —— 统计概率类需足够历史样本；只找到最近几个月做长期统计不可接受
3. **严肃对待计算公式** —— 财务指标必须用正确专业公式，算术必须准确
4. **严肃对待多步拆解** —— 复合条件不能直接跳过或简化
5. **惩罚数据虚构** —— 无法获取足够数据时明确局限，不编造
6. **单独惩罚日内精度缺失** —— 用户要求某时某分/盘中精度但用日线给确定金额 → 严重锚点错误
7. **记录执行效率** —— 大规模统计/复杂回测耗时过长且结果仍错，同时暴露效率+正确性问题

## 快速上手 Checklist

1. **步骤 0** 通读 `rubric/_index.md` + `golden_cases/_index.md`
2. **步骤 1** 六档制盲评，特别注意 `data_retrieval_accuracy` (20) + `time_inference` (15) + `calculation_accuracy` (15) 三大权重
3. **步骤 2** 阅读链路，定位根因
4. **步骤 3** 检查 6 个封顶（**特别注意 data_fabrication 上限 35**）
5. **步骤 4** 输出 JSON

**核心方法论**：「**取数对 + 时间对 + 公式对**才是基础，多步拆解和验证明细是上层。」
