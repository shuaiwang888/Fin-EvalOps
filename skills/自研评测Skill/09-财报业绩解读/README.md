# 09-财报业绩解读 Skill

> 自研模型「年报、季报、业绩快报、分红公告、现金流、毛利率、ROE、营收确认」等财报业绩解读类问题的评测协议。

---

## 一、Skill 定位与目标

**核心使命**：评测自研模型在**财报业绩解读**类问题上的最终答案和完整链路质量。

**关键定位**：

- **主锚点**：`text_answer`
- **辅助证据**：`chain`
- **设计哲学**：财报题不是背公式。好答案必须做到"**事实锚点 + 科目变化 + 业务/会计原因 + 财务影响 + 可持续性或投资含义**"。

## 三、适用范围

**适用**：

- 年报、季报、业绩快报、业绩预告、分红公告、官网公告内容解读
- 营收、净利润、扣非净利润、毛利率、ROE、现金流、负债、偿债能力、收入确认等指标变化原因
- 财报利好/利空、业绩对股价影响、持续性、估值与市场预期判断
- 会计差错更正、收入确认政策变更、非经常性损益、公允价值变动、套期保值、税务补缴等特殊事件解释
- 将财务数据与真实业务、行业周期、价格、订单、成本、产品结构、政策或公司公告原文连接

**不适用**：

- 纯条件选股
- 普通资讯问答
- 无财务报告语境的个股诊断
- KYC 投顾建议
- 同花顺产品客服问答

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | 分析题目 + 适用性 + 动态权重 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评最终答案（不看链路） | 各维度 `raw_score` + `evidence` |
| **步骤 2** | 链路诊断 + 根因 + `tool_usage` 评分 | `root_causes` |
| **步骤 3** | 应用封顶规则 | `caps` 数组 |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

**关键步骤强调**：

- **步骤 2**：用 `chain.tools[*].input/output` 判断**工具选择、输入质量、公告全文获取、结构化财务数据查询和交叉验证**

## 五、8 个评分维度

| 维度 | 建议权重 | 适用性 | 核心关注 |
|---|---:|---|---|
| `intent_understanding` 意图理解与任务完成 | 15 | **始终 relevant** | 是否回答用户真正要问的财报问题 |
| `report_data_accuracy` 财报数据与口径准确性 | 15 | relevant / supplementary | 具体指标/报告期/同比环比/分红/估值/会计口径 |
| `primary_evidence_quality` 公告全文与证据质量 | 15 | relevant / supplementary | 公告全文/年报附注/季报说明/会计差错公告/业绩说明会 |
| `causal_attribution_depth` 归因深度 | 15 | relevant / supplementary | 为什么/原因/怎么看/差异为什么大 |
| `business_financial_linkage` 业务财务联动 | 10 | relevant / supplementary | 财务变化连接业务/行业/价格/订单/成本 |

| `composition_credibility` 表达可信度 | 5 | **始终 supplementary** | |
| `tool_usage` 工具使用合理性 | 15 | **始终 relevant** | 财报题必须评估结构化数据/公告全文/搜索/交叉验证 |

## 六、6 个封顶规则（cap rules）

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `hard_fact_or_caliber_error` 硬性事实/口径错误 | **40** | 关键数据/科目/报告期/同比口径错 |
| `missing_primary_disclosure` 遗漏关键原始披露 | **55** | 没读到年报附注/季报变动原因/会计差错公告 |
| `wrong_special_event_explanation` 特殊事件解释错误 | **45** | 会计差错/收入确认政策/非经常性损益/公允价值解释错 |
| `surface_financial_formula_only` 只做表层财务公式解释 | **60** | 只解释 ROE/毛利率公式，不回答"这家公司这个报告期到底发生了什么" |
| `unverifiable_or_hallucinated_numbers` 不可验证/幻觉数字 | **50** | 编造数字或无来源 |
| `missing_required_conclusion` 缺少必要结论 | **65** | 没有可持续性/投资含义/股价影响判断 |

**特别注意**：如果答案推理看似自洽但遗漏公司明确披露的核心事件，应优先考虑 `missing_primary_disclosure` 或 `wrong_special_event_explanation`。

## 八、关键评分原则（保守评分 7 条）

1. **最终答案决定用户侧质量**，链路只用于归因
2. **财报题不是背公式** —— 必须做到"事实锚点 + 科目变化 + 业务/会计原因 + 财务影响 + 可持续性或投资含义"
3. **用户问"为什么"时，不能只解释 ROE/现金流/毛利率的公式** —— 必须回答"这家公司这个报告期到底发生了什么"
4. **用户前提错误时必须纠偏** —— 例如把全年亏损、累计报表、调整前数据、单季数据、收入/利润口径混淆
5. **强制检查公告全文和特定披露** —— 很多核心答案藏在**年报附注、季报变动原因、会计差错更正公告、分红公告、官网公告、问询函或业绩说明会**中
6. **能用公司披露原文或明确金额回答时，不要退化为泛化财务推理** —— 截图中的坏答案常见模式是"推理合理但没命中官方根因"
7. **评价股价影响时必须区分** —— 短期情绪、已反映程度、基本面持续性、估值锚和观察指标；不要把主观预测包装成确定结论

## 快速上手 Checklist

1. **步骤 0** 通读 `rubric/_index.md` 和 `golden_cases/_index.md`（30 案例）
2. **步骤 1** 检查**意图理解（15）**+**数据准确性（15）**+**公告证据质量（15）**+**归因深度（15）**四大权重
3. **步骤 2** **强制检查公告全文**（年报附注/季报变动原因/会计差错公告）
4. **步骤 3** 检查 6 个封顶（**特别注意 `missing_primary_disclosure` 上限 55**）
5. **步骤 4** 输出 JSON

**核心方法论**：「**事实锚点 + 科目变化 + 业务/会计原因 + 财务影响 + 可持续性**；公告全文必须查。」
