# 10-金融常识与语义理解 Skill

> 自研模型「金融概念、术语、交易规则、实体边界、指标口径、语义理解」类问题的评测协议。

---

## 一、Skill 定位与目标

**核心使命**：评测问财模型在**金融常识、金融语义理解、指标口径、交易规则、实体识别和用户真实意图补全**类问题上的回答质量。

**关键定位**：

- **主锚点**：`text_answer`
- **辅助证据**：`chain`（只用于工具使用和根因归因）
- **设计哲学**：评测金融**基础知识准确性**和**语义理解能力** —— 用户问"是什么/什么意思"，必须先解释概念，不能只给查询结果。

## 三、适用范围

**适用**：

- 财务/资金指标术语解释、量化筛选和口径判断：现金奶牛、净利润断层、主力控盘、PE 最小、最新季度 ROE
- 交易规则和市场制度理解：集合竞价、盘中最新价、ST 与 *ST、财报披露期
- 金融实体和产品边界：黄金现货 vs 黄金 ETF、基金公司 vs 旗下基金、豪威集团 vs 豪能股份
- 错别字、黑话、俚语、新题材和含混问法的语义纠错：心质/新质生产力、Token、老登股、敢死队
- 行业/个股/基金之间的语义关联：重仓半导体封测个股的 ETF、易方达基金表现

**不适用**：

- 主要考察事件选股排序（用 01）
- 严格指令遵循（用 11）
- 复杂投资逻辑推理（用 12）

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | 分析题目 + 适用性 + 动态权重 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评最终答案（不看链路） | 各维度 `raw_score` + `evidence` |
| **步骤 2** | 链路诊断 + 根因 + `tool_usage` 评分 | `root_causes` |
| **步骤 3** | 应用封顶规则 | `caps` 数组 |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

## 五、7 个评分维度

| 维度 | 建议权重 | 适用性 | 核心关注 |
|---|---:|---|---|
| `semantic_intent_alignment` 语义意图匹配 | 20 | **始终 relevant** | 是否读懂用户真实对象、真实任务和隐含语义 |
| `financial_term_understanding` 金融术语/规则理解 | 20 | relevant | 金融术语/交易规则/市场黑话/财务概念 |
| `entity_product_boundary` 实体与产品边界 | 15 | relevant | 同名公司/股票/基金/ETF/指数/现货/旗下产品 |
| `metric_caliber_accuracy` 指标公式与数据口径 | 15 | relevant | PE/ROE/主力控盘/ST/披露期/盘中价格等口径 |
| `timeliness_context` 时效上下文 | 10 | relevant / supplementary | 最新/近期/当下/盘中/报告期 |
| `credibility_expression` 可信解释与表达 | 10 | **始终 supplementary** | 若用户要求解释或定义则 relevant |
| `tool_usage` 工具使用合理性 | 10 | **始终 relevant** | |

**权重动态调整**：

- 题目只考察定义/常识 → `credibility_expression` 可提高到 15-20
- 涉及实体错配/产品边界 → `entity_product_boundary` 至少 15

## 六、6 个封顶规则（cap rules）

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `hard_concept_or_rule_error` 金融概念/规则硬错 | **40** | 集合竞价 9:20 当成已成交量 / 最新季度 ROE 用未披露报告期 |
| `wrong_entity_or_product` 实体/产品错误 | **45** | 黄金实物答成 ETF、豪威集团答成豪能股份 |
| `missed_core_definition` 遗漏核心定义 | **55** | 问定义但给指数/行情/查询结果 |
| `metric_caliber_unexplained_or_invalid` 指标口径未解释/无效 | **60** | PE 最小包含负 PE、主力控盘不解释定义 |
| `stale_or_wrong_time_context` 时效错误/过时 | **60** | "最新"/"近期"用旧数据 |
| `empty_generic_advice` 空泛通用建议 | **65** | 答案空泛/无解释价值 |

## 八、关键扣分方向（6 条）

1. **把用户真实对象理解错**：黄金实物问成 ETF、豪威集团答成豪能股份
2. **概念只会查数，不会解释**：问微盘股定义却给流通市值数据
3. **规则硬错**：集合竞价 9:20 当成已成交量、最新季度 ROE 使用未披露报告期
4. **指标口径失真**：PE 最小直接包含负 PE、主力控盘比例不解释定义
5. **新题材或黑话误判**：Token 只按区块链理解、老登股只按上市年限理解

---

## 九、安全护栏（6 条）

- 不要把相似金融产品混为一谈；现货、ETF、基金、指数、股票、基金公司和旗下基金要分清
- 不要用模型自造指标替代市场共识；若使用自定义指标，必须解释定义、口径和局限
- 对错别字和黑话要推断真实意图，但不能无证据强行联想
- 对"最新/近期/当下价格/盘中"等时间词要使用正确时点和披露周期
- 对 PE、ROE、ST、集合竞价等基础规则，硬性错误应重扣
- **数据表只能支撑答案，不能代替概念解释和语义判断**

## 十一、与其他 skill 的边界

- ❌ **不适用**：事件选股排序、严格指令遵循、复杂投资逻辑推理
- 与 **11-指令遵循能力**：本 skill 偏概念/语义/实体识别；11 偏主指令完成
- 与 **12-金融逻辑推理**：本 skill 偏静态概念；12 偏动态推演
- 与 **09-财报业绩解读**：本 skill 偏通用金融知识；09 偏具体公司财报

## 快速上手 Checklist

1. **步骤 0** 通读 `rubric/_index.md` 和 `golden_cases/_index.md`
2. **步骤 1** 重点检查**语义意图匹配（20）**+**金融术语理解（20）**两大权重（**注意 raw_score 是 0-5**）
3. **步骤 2** 优先看 5 个 L1 根因
4. **步骤 3** 检查 6 个封顶（**特别注意 `hard_concept_or_rule_error` 上限 40 和 `wrong_entity_or_product` 上限 45**）
5. **步骤 4** 输出 JSON

**核心方法论**：「**概念解释 + 实体识别 + 口径准确**；不要把数据查询当概念解释。」
