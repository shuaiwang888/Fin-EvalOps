# 07-交互澄清 Skill

> 自研模型「交互澄清、多轮投资对话、金融交易规则纠错」类问题的评测协议，沉淀**澄清、承接、纠错**三大主线。

---

## 一、Skill 定位与目标

**核心使命**：评测问财模型在**交互澄清场景**中的表现。

**关键定位**：

- **主锚点**：`text_answer`
- **辅助证据**：完整 `context`（历史轮次）+ `chain`
- **设计哲学**：07 文档的核心不是泛化投顾能力，而是**交互澄清闭环**。核心评分哲学是**"先判断用户能不能被直接回答"** —— 用户缺成本、仓位、股票、目标价、风险偏好、时间范围或交易权限时，应该**澄清、分层假设或明确口径**。

## 三、适用范围

**适用**：

- 模糊意图主动澄清/口径化/分层方案
- 多轮咨询中用户补充了持仓、成本、股票、亏损幅度、时间目标、风险偏好，需要**承接前文**而非重启回答
- 错误前提或交易规则陷阱：做空、北交所权限、科创板盘后固定价格交易、撤单时间、T+1/T+0、分红除权除息、国债逆回购计息
- 错别字、拼音/同音误写、重复代码、股票代码多输一位、行业黑话或口语简称识别
- 金融术语、技术形态、策略条件、选股口径咨询：把模糊词转成可核验定义（"短线"/"近期"/"回调比较多"/"业绩还在增长"）
- 需要**答案后续引导、监控、提醒、继续追问**形成咨询闭环

**不适用**：

- 普通事件资讯问答（用 08）
- 纯回测取数计算（用 02）
- 财报业绩归因（用 09）
- KYC 投顾适配（用 05）
- 文档/图片问答
- 严格指令遵循（用 11）

**边界判定**：若问题核心是"最新政策/新闻/事件影响"用 08；若核心是"诊股查数"用 03。

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | 分析题目 + 适用性 + 动态权重 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评最终答案（不看链路） | 各维度 `raw_score` + `evidence` |
| **步骤 2** | 链路诊断 + 根因 + `tool_usage` 评分 | `root_causes` |
| **步骤 3** | 应用封顶规则 | `caps` 数组 |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

**关键步骤强调**：

- **步骤 2**：用 `context` 和 `chain.plan` 判断意图理解、澄清策略、错误前提识别和多轮承接

## 五、11 个评分维度（动态权重）

| 维度 | 默认权重 | 核心关注 |
|---|---:|---|
| `intent_fulfillment` 意图满足度 | 12 | 用户真实澄清目标是否满足 |
| `ambiguity_clarification` 模糊澄清 | 16 | 是否识别不能直接答的状态，并问到关键变量 |
| `context_continuity` 上下文承接 | 14 | 用户补充后是否承接前轮澄清框架 |
| `entity_resolution` 实体识别 | 12 | 错别字、同音、异常代码、简称是否识别正确 |
| `financial_rule_and_premise` 金融规则与前提 | 14 | 交易规则、权限、税费、计息、错误前提是否纠正 |
| `assumption_definition` 假设口径 | 8 | 模糊条件是否转成可核验口径 |
| `actionability_and_risk_plan` 可执行与风险 | 8 | 澄清或纠错后是否有可执行落地和风险边界 |
| `evidence_grounding` 证据支撑 | 6 | 数据/规则/行情/公告/工具结果是否支撑结论 |
| `guidance_and_retention` 引导与留客 | 5 | 是否形成后续监控、提醒、复查或继续追问闭环 |
| `tool_usage` 工具使用合理性 | 3 | 工具选择、参数和交叉验证 |
| `latency_efficiency` 响应耗时 | 2 | 耗时和链路效率 |

**权重动态调整示例**：

- 错别字标的识别题 → 提高 `entity_resolution` 和 `tool_usage`
- 交易规则陷阱题 → 提高 `financial_rule_and_premise`
- 二轮补充持仓题 → 提高 `context_continuity`
- 模糊条件选股题 → 提高 `ambiguity_clarification`/`assumption_definition`/`actionability_and_risk_plan`
- 纯首轮咨询题 → `context_continuity` 可为 `not_applicable`

## 六、3 条主线校准

07 文档的核心是**交互澄清闭环**，评分时优先看三条主线：

1. **澄清与承接**：首轮能否问到关键变量，用户补充后二轮是否沿前轮框架推进
2. **语义与实体纠错**：是否贴近股民输入习惯处理错别字、同音、异常代码和多义标的
3. **规则与前提纠错**：是否先识别做空、北交所权限、撤单、T+1、分红税、逆回购计息等错误前提

`actionability_and_risk_plan` 和 `guidance_and_retention` 是澄清闭环的落地延伸，**不应压过上述三条主线**。

---

## 七、7 个封顶规则（cap rules）

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `wrong_financial_rule_or_unhandled_invalid_premise` 金融规则错/错误前提未纠 | (低) | 错误前提上继续给计划 |
| `wrong_entity_resolution` 实体识别错 | - | 错别字/同音误判 |
| `fabricated_or_unsupported_specific_advice` 编造/无支撑具体建议 | - | 假冒精确 |
| `context_break_after_clarification` 澄清后上下文断裂 | - | 二轮完全重启、换题、忽略用户补充 |
| `missing_required_clarification` 缺失必要澄清 | - | 应该澄清却直接答 |
| `inconsistent_time_or_definition_scope` 时间/定义口径不一致 | - | 模糊条件未口径化 |
| `generic_template_without_clarification_value` 无澄清价值的通用模板 | - | 模板化答案 |

| L1 | 核心问题 |
|---|---|
| `intent` 理解问题 | 意图理解 |

## 九、关键评分原则（保守评分 8 条）

1. **交互澄清的核心不是"答得多"**，而是先判断用户能不能被直接回答
2. **首轮澄清只是开始** —— 用户补充信息后，答案必须沿着前一轮建立的框架推进；若二轮完全重启、换题或忽略用户补充，要重扣 `context_continuity`
3. **金融交易规则陷阱必须先纠错** —— 错误前提上继续给计划是硬伤，即使后续分析看起来专业也应触发封顶
4. **错别字和异常代码要贴近真实股民输入习惯** —— 优先考虑 A 股常见标的、同音/近音、拼音习惯和问题语境
5. **模糊条件必须口径化** —— "近期/短线/适中/高度控盘/回调较多/业绩增长"等词，要给出筛选窗口、阈值、指标定义和局限
6. **对具体交易建议要可执行但不装确定** —— 好答案应包括前提、触发条件、仓位/节奏、风险边界、观察指标
7. **答案后引导不是泛泛"还有问题可以问我"**，而是给出贴合当前咨询的下一步：同类标的监控、风险提醒、财报/分红日提醒、价格触发跟踪、候选池复查等
8. **速度可作为辅助扣分项** —— 专家数据中该场景问财质量和速度双低；但不要让耗时掩盖事实错误、规则错误或承接断裂

## 快速上手 Checklist

1. **步骤 0** 通读 `rubric/_index.md`（11 维度）和 `golden_cases/_index.md`（41 案例）
2. **步骤 1** 检查**三大主线**：
   - 澄清与承接（`ambiguity_clarification` 16 + `context_continuity` 14）
   - 语义与实体纠错（`entity_resolution` 12）
   - 规则与前提纠错（`financial_rule_and_premise` 14）
3. **步骤 2** 特别检查 `context` 根因（多轮承接断裂）
4. **步骤 3** 检查 7 个封顶
5. **步骤 4** 输出 JSON

**核心方法论**：「**先判断能不能直接答 → 缺什么就澄清什么 → 用户补充后要承接 → 模糊词要口径化**。」
