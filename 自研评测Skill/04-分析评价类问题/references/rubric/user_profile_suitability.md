# `user_profile_suitability` 用户画像适配

判断答案是否把投资分析转化为适合该用户的建议，而不是只说明标的或市场“看起来不错”。

关注点：
- 是否识别并使用用户风险偏好、投资期限、资金规模、收益目标、交易经验、持仓背景、成本和浮盈浮亏。
- 用户说“适合我”“结合我的目标风险”“我有多少资金”时，是否主动利用 `context`、画像工具或当前自述；画像缺失时是否说明依据不足并采用分层假设或必要追问。
- 推荐对象是否与用户画像匹配：稳健用户不应被默认推向高波动主题、窄行业、短线热点或单票重仓。
- 是否解释“为什么适合这个用户”：组合角色、仓位角色、期限角色、风险收益取舍，而不只是解释“为什么这个标的好”。
- 基金/ETF/组合建议是否关注宽基/行业/风格暴露、波动、回撤、同类比较和配置位置。

常见失败模式：
- 用户问“我适合什么”，答案完全不看历史提问或画像，直接给热门标的。
- 编造用户是稳健型、激进型、短线型、长期型，并据此推荐。
- 推荐两只 ETF 却默认给医疗、5G 等窄行业高波动主题，缺少风险承受和配置角色判断。
- 对“20 万、结合目标风险”只给泛泛资产配置，没有核心/卫星、仓位、筛选标准和买卖规则。
- 只说明行业逻辑，不说明这类资产在用户组合中的位置。

## 边界说明

- 与 `scenario_emotion_recognition` 的区分：本维度负责用户画像数据（风险偏好、资金规模、投资期限、持仓背景等）的识别和使用；`scenario_emotion_recognition` 负责情绪状态和风险处境的识别。当用户既表达情绪状态又提供了画像数据时，两个维度独立评分，不重复扣分。

## 适用性判断

- **relevant**：适合我、结合目标/风险/持仓/成本、推荐股票/基金/ETF/行业、配置、仓位、解套、割肉、加仓。
- **supplementary**：普通买卖分析或持有诊断，即使用户未显式要求个性化，也需要基本适配边界。
- **not_applicable**：完全客观事实查询、单纯行情查询、无需用户适配的资料总结。
