# `tool_usage` 工具使用合理性

此维度在根因诊断阶段评分，因为需要阅读 `chain.plan` 和 `chain.tools`。

判断规划链路是否选对工具、用对工具、用足工具，并正确利用工具输出。

评分前先阅读 [工具列表](../tool_list/_index.md)。

关注点：
- 结构化行情、财务、基金、指数数据优先用 FinQuery
- 最新消息、事件、政策、公告、研报、调研线索优先用 Search，必要时用 AccessingFullText 深读
- 个人化推荐、持仓决策、适合我、结合目标风险等问题，应优先检查可见 `context`、用户画像工具或画像存储；缺少画像时应在答案中说明并分层处理
- 需要计算历史分位、回撤、对比指标时，应使用 CodeInterpreter 或结构化工具结果
- 单次工具失败或返回 0 时，应判断是事实为 0、口径错误还是工具表达问题
- 工具输出中有关键字段时，最终答案应正确引用和解释

常见失败模式：
- 用普通 Search 替代结构化金融查询，或用 FinQuery 查询非结构化消息背景
- 查消息面却没有查“新闻/公告/研报/调研”等合适后缀或来源
- 工具返回 0 条后直接推断结论，没有验证口径
- 查询到了数据但没有用于核心判断
- 需要专业深层资料时没有意识到来源缺口
- 推荐问题未读取或未利用用户画像/历史上下文，却直接生成个人投资建议
- 历史阶段、估值分位、盈利确定性或多资产比较问题，没有调用足以支撑比较的数据工具

## 边界说明

- 与 `evidence_source_quality` 的区分：本维度评判链路中工具选择和调用策略是否正确；`evidence_source_quality` 评判最终答案的证据是否充分可信。若工具选择正确但数据源本身不足导致证据缺失，属于 `evidence_source_quality` 扣分而非本维度。

## 适用性判断

- **始终 relevant**。所有线上链路均需评估工具使用策略。
