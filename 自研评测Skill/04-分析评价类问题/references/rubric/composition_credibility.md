# `composition_credibility` 表达可信度

判断最终答案是否清晰、可信、专业，是否把关键逻辑讲出来。

关注点：
- 结构是否围绕用户问题展开，而不是模板堆叠
- 是否明确区分事实、推断、观点和不确定性
- 是否有足够具体的证据指向，避免“市场认为、研究显示、资金关注”等空泛表述
- 是否把链路中的关键发现呈现在最终答案中
- 是否避免过度主观、含糊、说一半藏一半
- 是否避免“看起来像完整投顾说明书”，但没有回答为什么适合当前用户、为什么现在这样配、下一步如何执行
- 是否避免过度啰嗦、计算细节和技术指标淹没核心决策
- 是否控制信息密度：答案可以长，但每一段都应服务核心判断、证据或行动建议
- 是否在没有重大消息或资料不足时直说边界，而不是用无关信息填满版面

常见失败模式：
- 表格很长但没有核心解读
- 观点像资讯拼接稿，没有私人投顾式判断
- 链路里有关键判断，最终答案丢失
- 用漂亮话掩盖证据不足
- 同一类个人化推荐每次结论大幅变化，却没有说明新信息、市场变化或假设差异
- 反复解释同一表象，导致用户真正关心的逻辑变化、切换理由或风险没有被回答

## 适用性判断

- **始终 supplementary**。表达不应压过核心逻辑，但会影响用户信任。
