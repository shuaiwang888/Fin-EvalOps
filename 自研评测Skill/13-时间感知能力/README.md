# 13-时间感知能力 Skill

> 自研模型「时间推理、时间口径、交易日历、数据时点」类问题的评测协议。

---

## 一、Skill 定位与目标

**核心使命**：评测我方模型是否**正确理解并使用时间**。

**关键定位**：

- **主锚点**：`text_answer`
- **关键输入**：`request_time` / `current_date` / `timestamp`（请求时间）+ 用户时区
- **辅助证据**：`chain`
- **设计哲学**：时间感知题**先判"时间前提是否成立"，再判金融分析是否漂亮**。若市场当天休市、日期不存在交易、用户的星期/日期前提错误，直接套行情模板是严重错误。

## 三、适用范围

**适用**：

- 相对时间：今天、昨天、明天、下周一、下礼拜二、去年、今年、近 N 日、前 N 个交易日、年中、季末、截至某日
- 交易日历：A 股、港股、美股、期货、外汇、贵金属等市场是否开盘、节假日休市、半日市、盘前/盘中/盘后、跨时区日期
- 日期推理：自然日与交易日、周几、节假日顺延、未来日期、历史日期、日期与星期不一致
- 数据时点：今日行情、最新价格、最近公告、最新财报、年报/季报披露期、数据 as-of 时间、旧数据冒充当日数据
- 时间前提纠错：用户问题含错误日期、错误开盘前提、错误年份或模糊时间时，答案是否主动澄清

**不适用**：

- 完全不涉及时间边界的普通事实问答
- 纯投资逻辑分析
- 不依赖当前日期的数据解释

**边界判定**：若问题同时属于诊股查数、分析评价或事件选股，但错误主要来自**时间锚点/交易日历/数据时点**，本 skill 应优先或并行使用。

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | **抽取时间锚点** + 适用性 + 动态权重 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评最终答案（不看链路） | 各维度 `raw_score` + `evidence` |
| **步骤 2** | 链路诊断 + 根因 + `tool_usage` 评分 | `root_causes` |
| **步骤 3** | 应用封顶规则 | `caps` 数组 |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

**关键步骤强调**：

- **步骤 0**：先只看 `question`、必要 `context` 和可见请求时间，抽取**显式日期、相对日期、周期词、交易日词、市场/品种、数据口径词**；评测所需的标准答案锚点
- **步骤 2**：用 `chain.plan` 判断**是否正确识别时间锚点、是否决定核验交易日历和数据 as-of**；用 `chain.tools[*]` 判断**是否查了正确日期、市场、证券代码、报告期和工具返回日期**

## 五、8 个评分维度

| 维度 | 建议权重 | 适用性 | 核心关注 |
|---|---:|---|---|
| `temporal_intent_recognition` 时间意图识别 | 15 | 任何含相对时间/日期/周几/交易日/最新/今天/去年 | 识别时间意图 |
| `anchor_date_resolution` 锚点日期解析 | 15 | 涉及今天/昨天/明天/下周/去年/年中/近 N 日/前 N 个交易日 | 解析锚点日期 |
| `market_calendar_status` 交易日历状态 | 15 | 涉及开盘/走势/今天涨跌/港股/A 股/美股/期货/外汇 | 交易日历判断 |
| `data_asof_freshness` 数据时点新鲜度 | 15 | 涉及今天为什么涨跌/最新价/最新公告/最近数据/当前行情/近期表现 | 数据时点 |
| `period_disclosure_mapping` 财报期间映射 | 10 | 涉及去年营收/今年一季报/年中分红/某年报/最新财报/同比环比期间 | 财报期间映射 |
| `premise_correction_clarification` 前提纠错与澄清 | 10 | 涉及错误日期/错误星期/休市却问涨跌/上下文时间不明 | 纠错与澄清 |
| `answer_composition_credibility` 答案可信表达 | 10 | 所有时间感知题 | 表达可信 |
| `tool_usage` 工具使用合理性 | 10 | 需要外部交易日历/行情/公告/财报/分红/跨市场数据/最新状态 | 工具使用 |

**权重动态调整**：

- 交易日/休市/今日涨跌题 → `market_calendar_status`/`data_asof_freshness`/`premise_correction_clarification` 最高
- 相对日期/周几题 → `anchor_date_resolution` 最高，`temporal_intent_recognition` 次高
- 财报/分红/报告期题 → `period_disclosure_mapping` 最高，`data_asof_freshness` 次高
- 最新/最近题 → `data_asof_freshness` 和 `tool_usage` 提高
- 表达维度通常为 5-10

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `hard_wrong_anchor_date` 硬性锚点日期错误 | **40** | 关键日期/星期/交易日错 |

| `missing_required_premise_correction` 缺失必要前提纠错 | **50** | 用户错误前提未主动澄清 |
| `fiscal_period_disclosure_error` 财报期间披露错误 | **50** | 去年/今年/年中映射错 |
| `fabricated_time_fact` 编造时间事实 | **30** | 编造交易日/披露期/数据时点 |

## 八、关键评分原则（保守评分 7 条）

1. **时间感知题先判"时间前提是否成立"**，再判金融分析是否漂亮
2. **今日/最新类问题必须说明 as-of 时间** —— 用上一交易日/旧行情/历史财报回答时必须显式说明原因和限制
3. **"去年/今年/年中"按用户请求时间解析** —— 不得因为最新可得财报只有更早年度就偷偷改年份；若目标报告期未披露，应先说明未披露，再给最新可得数据作为替代
4. **下周/下礼拜/前 N 个交易日必须区分自然日、交易日和节假日顺延** —— 市场休市不等于把问题自动平移到下一个交易日
5. **跨市场问题必须按对应市场日历判定** —— A 股/港股/美股/伦敦金/期货的休市和时区不能混用
6. **对用户错误前提要纠错** —— 高质量答案会先说"今天该市场无交易/该日期不是开盘日/你说的日期与星期不一致"，再给可用替代口径
7. **只要最终答案让用户误以为错误日期/错误年份/旧数据就是当前事实，必须重扣** —— 链路里查对了但最终没说清，也不能高分

## 十一、与其他 skill 的边界

- ❌ **不适用**：完全不涉及时间边界的普通事实问答、纯投资逻辑分析、不依赖当前日期的数据解释
- 与 **03-诊股查数**：本 skill 偏时间锚点；03 偏个股数据
- 与 **08-资讯知识问答**：本 skill 偏时间前提；08 偏资讯解释
- 与 **09-财报业绩解读**：本 skill 偏财报期间映射；09 偏财报归因
