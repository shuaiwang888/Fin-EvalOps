# 自研评测 Skill 体系（13 个 Skill 总览）

> 自研金融模型评测的**13 个细分场景评测协议**总览，覆盖从选股、诊股、查数、回测，到分析评价、KYC 推荐、交互澄清、时间感知、逻辑推理等完整金融问答能力图谱。

本目录是**自研金融 Agent 评测的协议族**，13 个 skill 共享相同的「5 步评测协议」+「六档分量表」+「封顶规则」+「根因归因」架构，但针对**不同金融问答场景**使用不同维度和 hard checks。

## 二、统一架构：5 步评测协议

所有 13 个 skill 共享以下架构：

### 2.1 评测流程（5 步）

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | 分析题目 + 适用性判断 + 动态权重分配 | `weight_assignment`（总和必须 = 100） |
| **步骤 1** | 盲评最终答案（不看链路） | 各维度 `raw_score`（0/20/40/60/80/100）+ `evidence` |
| **步骤 2** | 链路诊断 + 根因归因 + `tool_usage` 评分 | `root_causes` 列表 |
| **步骤 3** | 应用封顶规则 | `caps` 数组（多个触发取最低上限） |
| **步骤 4** | 序列化 JSON 输出 | 按各 skill 的 `output-schema_zh.md` |

### 2.2 六档分制（raw_score）

`100` 完美 / `80` 极轻微不足 / `60` 基本满足 / `40` 关键缺失 / `20` 仅触及边角 / `0` 完全未响应

加权公式：`加权分 = raw_score / 100 × dynamic_weight`

### 2.3 三大评测原则

- **最终答案决定用户侧质量**，链路只用于归因
- **不要把"有表格/有指标/有工具调用"自动视为高质量**
- **隐藏规划不能覆盖最终答案触发的封顶规则**

### 2.4 根因归因 L1 阶段（5-8 个）

虽然各 skill 略有差异，但基本覆盖：

- `intent` 意图理解
- `context` 上下文/KYC（05、07 独有）
- `coverage` 任务覆盖（06 独有）
- `evidence` 证据检索
- `tool` 工具策略
- `data_logic` 数据/逻辑（06 独有）
- `reasoning` 推理
- `capability_gap` 能力/数据源缺口（04 独有）
- `safety_or_compliance` 安全/合规（05 独有）
- `latency` 响应效率（06 独有）
- `composition` 答案组织

### 2.5 根因选择规则

按 raw_score 升序 + 权重降序 + 维度名字母序排列；最多 8 个；活跃维度 raw_score ≥ 60 且无封顶时允许空数组。

### 3.3 关键边界判定（重要！）

| 模糊情况 | 判定方法 |
|---|---|
| 涉及受益标的的事件 vs 选股 | 看**结论落点**：解释事件用 08；选股排序用 01 |
| 单一事件→一组标的 vs 多子任务 | 单一用 01；多子任务用 06 |
| 诊股查数 vs 回测计算 | 诊断 + 取数用 03；公式 + 时间 + 多步用 02 |
| 分析评价 vs KYC 推荐 | "是否需要给用户做适配后的决策建议"——是 → 05；否 → 04 |
| 事件资讯 vs 选股 | 解释事件用 08；排序选股用 01 |
| 财报归因 vs 普通诊断 | 财报/业绩语境用 09；无财报语境用 03 |
| 时间问题 vs 其他 | 错误主要来自时间锚点/交易日历/数据时点 → 13；否则用对应 skill |
| 多轮对话 vs 单次指令 | 多轮承接用 07；单次指令用 11 |
| 投资逻辑 vs 取数计算 | 推理结论用 12；取数计算用 02 |

## 十一、整体设计哲学

### 11.1 共同的"3 大原则"

1. **最终答案决定用户侧质量** —— 链路只用于归因
2. **不要把"复杂/有数据/有图表"自动视为高质量** —— 内容需匹配用户真实意图
3. **隐藏规划不能覆盖最终答案触发的封顶规则** —— 好的链路救不了差的答案

### 11.2 共同的"5 步流程"

`分析题目 → 盲评打分 → 链路诊断 → 封顶规则 → 序列化输出`

### 11.3 共同的"维度 + 封顶 + 根因"三角

- **维度**：动态权重评估每个质量方面
- **封顶**：硬性错误限制最终分
- **根因**：归因到 5-8 个 L1 阶段

### 11.4 共同的"专家案例 + image_annotation_anchors"

每个 skill 都有：
- `_index.md` 沉淀 hard checks
- `image_annotation_anchors.md`（部分 skill）沉淀截图人工批注

### 11.5 共同的"JSON schema 输出"

- `weight_assignment` / `skipped_dimensions` / `matched_golden_cases`
- `dimension_scores`（仅活跃维度）
- `caps` / `root_causes` / `narrative_review`
