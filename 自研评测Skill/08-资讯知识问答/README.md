# 08-资讯知识问答 Skill

> 自研模型「资讯 / 知识问答」类问题的评测协议，沉淀事件影响、市场异动、新闻/政策解读、调研纪要等场景的评分细则。

---

## 一、Skill 定位与目标

**核心使命**：评测自研模型在「**资讯 / 知识问答 / consultation-and-qa**」场景下的最终回答。

**关键定位**：

- **主锚点**：`text_answer`
- **辅助证据**：`chain` —— 只用于工具使用与根因归因
- **设计哲学**：用户常表面问"是什么/为什么"，实际要"**影响、受益标的、怎么判断、是否可持续**"。信息密度高不等于好答案。

## 三、适用范围

**适用**：

- 最新政策、监管、产业数据、公司事件的梳理与评价
- 某新闻/政策/宏观事件/产业事件对 A 股行业/标的的影响
- 某公司项目/产能/海外建厂/新产品/供应链进展是否有新变化
- 某板块/主题/大盘当天/近期异动的主要原因
- 市场小段子、金融大V文章、调研纪要、官媒截图等非标准资讯对股价或热点的解释
- 多个热门方向的新闻密度、政策层级、产业落地进度横向比较

**不适用**：

- 纯行情查询
- 纯财务指标查询
- 无资讯理解要求的条件选股
- 普通客服问答
- 泛泛投资建议

**与 01 的边界**：落点是"解释事件本身、影响链"用 08；落点是"选出/排序受益标的"用 01。当两者都涉及受益标的时，**优先看答案结构**：以个股列表/排序/梯队划分为核心输出的归 01，以事件梳理/影响分析/行业判断为主线的归 08。

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | 分析题目 + 适用性 + 动态权重 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评最终答案（不看链路） | 各维度 `raw_score` + `evidence` |
| **步骤 2** | 链路诊断 + 根因 + `tool_usage` 评分 | `root_causes` |
| **步骤 3** | 应用封顶规则 | `caps` 数组 |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

## 五、9 个评分维度

| 维度 | 建议权重 | 适用性 | 核心关注 |
|---|---:|---|---|
| `intent_fulfillment` 意图满足度 | 15 | **始终 relevant** | 显性问题和隐含投资诉求 |
| `timeliness_fact_boundary` 时效性与事实边界 | 15 | relevant / supplementary | "最新/近期/近两周/当天"严格时间 |
| `fact_evidence_quality` 事实证据质量 | 15 | **始终 relevant** | 事实/数据口径/来源类型/可核验性 |
| `information_integration` 资讯整合与比较 | 12 | relevant / supplementary | 多政策/监管/产业/公司事件整合或横向比较 |
| `investment_mapping` 投资映射与落地 | 12 | relevant / NA | 影响/受益标的/行业方向/A 股映射 |
| `core_signal_extraction` 核心信号提炼 | 10 | relevant / supplementary | 市场异动/热点/传闻/政策影响/比较判断 |
| `nonstandard_source_awareness` 非标准资讯意识 | 8 | relevant / supplementary | 市场小段子/调研纪要/大V文章/官媒截图 |
| `credibility_expression` 可信表达 | 5 | **始终 supplementary** | 语气/边界/风险提示/可读性 |
| `tool_usage` 工具使用合理性 | 8 | **始终 relevant** | 检索/交叉验证/来源选择/工具链路 |

**权重动态调整**：

- 强依赖时间 → 提高 `timeliness_fact_boundary` 和 `fact_evidence_quality`
- 解释市场异动/热点持续性 → 提高 `core_signal_extraction` 和 `nonstandard_source_awareness`
- 要求"对应标的/影响/受益" → 提高 `investment_mapping`

## 六、5 个封顶规则（cap rules）

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `hard_time_or_fact_error` 硬性时间/事实错误 | **40** | 关键年份/政策历史/数据口径/项目进展错 |
| `stale_or_wrong_evidence` 证据过时/来源类型错 | **50** | 旧公告/旧数据冒充最新 |
| `template_answer_without_signal` 模板化回答未抓核心信号 | **55** | 四大面套模板未抓真实催化剂 |
| `data_dump_without_judgment` 数据堆砌无判断 | **60** | 大段素材无主线 |
| `unverified_rumor_as_fact` 传闻当事实 | **50** | 未证实内容写成确定事实 |

## 八、关键评分原则（保守评分 + 安全护栏 10 条）

**保守评分 5 条**：

1. **不计算 weighted_points/absolute_score_pre_cap/final_score**（调用方处理）
2. "最新/近两周/截至某日/当天/这周"等表达必须严格核对时间范围
3. **信息密度高不等于好答案** —— 没有核心事件、时间点、证据类型、影响链条、标的/行业映射，只能按素材堆砌扣分
4. 对市场小段子/调研纪要/大V文章/官媒截图等来源保持**来源类型敏感** —— 区分传闻、确认事实、主观解读
5. 对非公开/半公开信息要审慎表达，允许指出"需核验"或"传闻口径"，不能把未证实内容写成确定事实

**安全护栏 5 条**：

1. **严肃对待事实硬错** —— 关键年份/政策历史定位/数据口径/项目进展/量产时间/公司产品边界错误 → 显著封顶
2. **严肃对待时间边界** —— 不得把未来数据/旧公告/长期主线混入"最新/近两周/当天"答案
3. **严肃对待用户真实意图** —— 表面问"是什么/为什么"，实际要"影响/受益标的/怎么判断/是否可持续"
4. **惩罚模板化回答** —— 基本面/技术面/资金面/消息面四段式若没抓到真实催化剂，应低分
5. **惩罚宽泛标的罗列** —— 必须给出主线、催化剂、受益环节、核心标的和边界

**对横向比较题要求收敛结论**：新闻密度、政策层级、产业落地、概念热度等维度必须可比较，不能三段素材拼接。

## 快速上手 Checklist

1. **步骤 0** 通读 `rubric/_index.md` 和 `golden_cases/_index.md`（21 案例）
2. **步骤 1** 重点检查**时效性（15 分）**和**事实证据质量（15 分）**和**意图满足度（15 分）**三大权重
3. **步骤 2** 优先看 5 个 L1 根因
4. **步骤 3** 检查 5 个封顶（**特别注意 `hard_time_or_fact_error` 上限 40**）
5. **步骤 4** 输出 JSON

**核心方法论**：「**事实+时间+证据+影响映射+核心信号**；不要把未证实传闻写成确定事实。」
