# `ranking_judgment` 排序判断（建议权重 15）

判断答案是否用明确的逻辑对目标进行了排序。

关注点：
- 当用户要求排序时，给出了排序、分层或排列
- 有明确的标准，如受益纯度、盈利杠杆、确定性、弹性或市场领导力
- 即使用户只说"龙头""最相关""收益最大""订单多""业绩利好"，也要给出核心/次核心/边缘或第一梯队/第二梯队
- 排序应优先基于事件贴合度、受益纯度、业务占比、盈利弹性和确定性，再辅以行情热度、资金流、换手、弹性
- **边界说明**：本维度负责"是否对识别出的标的给出了合理排序"；"是否正确识别了受益链条和层级"由 `industry_mapping` 负责
- 对概念池或交集查询，不能只按涨幅、市值、成交额机械排序；必须解释为什么这些排序标准适合当前题目
- 对短线/交易语境，应补充交易性价比维度：市值大小、营收/利润弹性、流通盘、换手、量比、是否新高、回撤风险、是否已经充分演绎
- 对产业链题，应按"核心材料/设备/系统/应用/配套"或"龙头/弹性/稳健"分层，而非一张混合名单

常见失败模式：
- 用户明确要求排序但未给出
- 按通用表格排序隐藏了实际投资逻辑
- 标的过多没有主次，用户无法一眼定位龙头、中军、弹性标的或边缘补涨
- 事件题中过度依赖行情片面指标，忽略事件相关度和受益逻辑
- 只讲产业逻辑，不比较谁市值营收比最低、谁市值更小弹性更大、谁短线资金更可能偏好

## 适用性判断

- **relevant**: 用户明确要求排序、排名、优先级判断（如"从最利好到一般"、"哪些最受益"、"领涨"、"龙头"、"弹性最大"、"可投资价值排序"）
- **supplementary**: 用户未明确要求排序但问题隐含优先级判断需求（如"有哪些概念股"可能隐含谁更强的判断）
- **not_applicable**: 用户仅要求列出符合条件的标的，无排序需求
