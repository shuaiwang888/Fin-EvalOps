# 01-事件与概念选股 Skill

> 自研模型「事件 / 概念驱动选股」类问题的端到端评测协议，沉淀排序、产业链映射、事件抽象、逻辑闭环等评分细则与根因归因体系。

---

## 一、Skill 定位与目标

**核心使命**：用稳定协议评测自研模型在「事件 / 概念驱动选股」类问题上的**最终答案质量**和**完整链路质量**。

**关键定位**：

- **主锚点**：`text_answer`（最终答案）—— 盲评打分
- **辅助证据**：`chain`（完整规划链路）—— 根因归因
- **设计哲学**：选股类问题的核心不是把概念成分股倒出来，而是完成**概念脱水 → 受益纯度划分 → 核心标的提炼 → 可执行排序**。

## 三、适用范围

**适用**：

- 事件/政策/产品/战争/地缘等驱动下的选股或排序
- 概念股领涨/爆发/排名第一
- 主题核心受益 vs 边缘受益标的
- 产业链、材料、设备、客户供货、主营产品对应 A 股标的
- 美股/海外巨头映射到沪深可比公司
- 主题交集、政策方向下的主线拆解

**不适用**：纯行情查询、个股诊断、投资组合建议、纯条件筛选、无事件/主题推理层。

**与 08 的边界**：落点是"选出 / 排序受益标的"用 01；落点是"解释事件 / 影响链"用 08。**与 06 的边界**：单一事件→一组标的用 01；多子任务+跨多源信息整合用 06。

## 四、5 步执行协议

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| **步骤 0** | 适用性判断 + 动态权重 + 案例命中 | `weight_assignment`（总和=100） |
| **步骤 1** | 盲评最终答案（不看链路） | 各维度 `raw_score`（0/20/40/60/80/100）+ `evidence` |
| **步骤 2** | 链路诊断 + 根因归因 + `tool_usage` 评分 | `root_causes` 列表 |
| **步骤 3** | 应用封顶规则 | `caps` 数组（取最低上限） |
| **步骤 4** | 序列化 JSON 输出 | 按 `output-schema_zh.md` |

## 五、8 个评分维度

| 维度 | 默认权重 | 适用性 | 核心关注 |
|---|---:|---|---|
| `intent_fulfillment` 意图满足度 | 20 | **始终 relevant** | 用户问题是否被完整回答 |
| `event_abstraction` 事件抽象度 | 15 | relevant / supplementary / NA | 事件脱水、核心驱动力、主题识别 |
| `industry_mapping` 产业链映射 | 10 | relevant / NA | 上游材料、设备、客户供货、产能份额、海外映射 |
| `ranking_judgment` 排序判断 | 15 | relevant / supplementary | 最受益/龙头/弹性最大；隐含排序也要落地 |
| `logic_closure` 逻辑闭环 | 15 | **始终 relevant** | 事件→受益纯度→标的→排序理由的闭环 |
| `timeliness_fact_boundary` 时效性与事实边界 | 10 | relevant / supplementary | "最新/近期/截至某日"严格时间边界 |
| `credibility_expression` 可信度与表达 | 5 | **始终 supplementary** | 表达质量始终有参考 |
| `tool_usage` 工具使用合理性 | 10 | **始终 relevant** | 工具选择、参数、约束处理 |

## 六、6 个封顶规则（cap rules）

| 规则 | 上限 | 触发场景 |
|---|---:|---|
| `hard_time_or_fact_error` 硬性时间/事实错误 | **40** | 核心事件年份、文件号、政策定位、产业边界错误 |
| `missing_required_ranking` 遗漏必要排序 | **60** | 用户明确要求排序/优先级但答案无排序 |
| `data_dump_without_core_rationale` 数据堆砌无核心论证 | **55** | 表格多但没有受益推理、纯度划分、核心标的提炼 |
| `wrong_evidence_type` 证据类型错误 | **50** | 用户要新闻/事件触发但给的是通用报告或宽泛概念 |
| `unverifiable_subjective_expression` 不可验证的主观表达 | **65** | "强/弱/龙头"等无量化指标、业务口径或来源支撑 |
| `forced_mapping_or_entity_boundary_error` 强行映射/实体边界错误 | **50** | A 股对标美股/海外巨头时强行凑相似 |

## 七、5 个 L1 根因归因体系

| L1 | 核心问题 | L2 数量 |
|---|---|---:|
| `intent` 理解问题 | 隐含意图、子任务、范围约束、模糊时间 | 4 |
| `evidence` 检索信息 | 数据值、深度、覆盖、非公开资料、时效 | 6 |
| `tool` 选择与执行工具 | 工具选择、参数、上限、SQL 解析、交叉验证、效率 | 5 |
| `reasoning` 推导投资逻辑 | 事件抽象、产业链、排序、闭环、案例 | 8 |
| `composition` 组织答案 | 明细、过程、呈现、解释、压缩 | 5 |

**根因选择规则**：按 raw_score 升序 + 权重降序；最多 8 个；活跃维度 raw_score ≥ 60 且无封顶时允许空数组。

## 八、40 个专家案例（golden cases）

文档沉淀了 40 个专家案例 hard checks，涵盖：

- 事件驱动类：战争/政策/产品/地缘事件受益股
- 概念股：领涨/爆发/排名前列
- 产业链映射：上游材料/中游设备/下游应用
- 主题交集与梯队划分
- 海外巨头对标 A 股

**跨案例锚点**：

- 严肃对待隐含意图（"最受益"/"领涨"需要优先级判断）
- 严肃对待时间范围（"最新"/"近两天"严格边界）
- 严肃对待证据类型（新闻 ≠ 通用报告）
- 惩罚"只会取数"（概念股成分股≠好答案）
- 区分直接与间接关联（主营/副业、品牌厂/代工厂）
- 映射类比对保持克制（"没有完全对标"是可以接受的）

---

## 九、关键评分原则（安全护栏 8 条）

1. **严肃对待隐含意图** —— "最受益/领涨/最相关"需要优先级判断和理由
2. **严肃对待时间范围** —— "最新/最近/截至某日/近两天"严格时间边界
3. **严肃对待证据类型** —— 用户要新闻/事件触发，不能用通用报告或概念简介替代
4. **惩罚数据堆砌** —— 没有投资论点、排序逻辑、受益推理的表格不是好答案
5. **惩罚"只会取数"** —— 核心是概念脱水、受益纯度、核心标的、可执行排序
6. **要求硬证据支撑** —— "产能最高/订单多/市占率高/对标海外巨头"必须有量化指标或来源
7. **区分直接与间接关联** —— 主营/副业、直接供货/间接供应链、核心产品/边缘材料
8. **不要让行情指标压倒事件相关度** —— 事件贴合度和受益纯度优先于资金流、弹性、涨幅

## 十一、JSON 输出契约

**schema_version** = `event-concept-stock-selection/v3`（动态权重 v3 体系）

**核心字段**：

- `weight_assignment` / `skipped_dimensions` / `matched_golden_cases`
- `dimension_scores`（仅活跃维度，0/20/40/60/80/100）
- `caps` / `root_causes`（L1 + L2 + dimension + confidence + evidence）
- `narrative_review`

**不输出** `weighted_points` / `absolute_score_pre_cap` / `final_score`（由调用方计算）。

---

## 十二、与其他 skill 的边界

- ❌ **不适用**：普通行情查询、个股诊断、投资组合建议、纯条件筛选
- 与 **08-资讯知识问答**：以"选股排序"还是"事件解释"为结论落点
- 与 **06-复合意图**：单一事件→一组标的用 01；多子任务整合用 06
- 与 **03-诊股查数**：本 skill 偏事件推理，03 偏查数诊断
- 与 **04-分析评价**：本 skill 偏排序，04 偏评价归因

---

## 快速上手 Checklist

1. 评测时**先看 SKILL_zh.md 的 8 条安全护栏** —— 评分哲学总纲
2. **步骤 0** 必读 `rubric/_index.md` + `golden_cases/_index.md`（40 案例）
3. **步骤 1** 用「六档制 + 证据绑定」盲评最终答案
4. **步骤 2** 必须阅读 `chain`，定位根因到 5 个 L1
5. **步骤 3** 检查 6 个封顶，取最低上限
6. **步骤 4** 按 `output-schema_zh.md` 输出 JSON

**核心方法论**：「概念成分股列表≠好答案，**事件脱水 + 受益纯度 + 排序理由**才是」。
