# `tool_usage` 工具使用合理性

判断模型链路中的工具选择、工具输入、工具输出读取和证据转化是否支撑 KYC 推荐建议。

关注点：
- 是否根据任务调用合适工具：行情/财务/估值/基金/宏观数据优先用 FinQuery，新闻和非结构化信息用 Search，历史表现或策略验证用 BackTest，复杂计算用 CodeInterpreter
- 05 类推荐建议问题中，是否主动读取、调用、检索或引用用户 KYC 数据；KYC 数据来源可以是画像工具、画像存储、历史 `context`、当前问题自述或链路中可见画像结果
- 是否用已获取的用户风险、目标、期限、资金、持仓、交易经验或风格指导检索和筛选
- 是否查询了推荐所需的关键证据，而不是只查容易查到的信息
- 是否正确解读工具输出，并把结果转化为最终推荐
- 是否避免工具调用过多导致低效、重复或偏离用户任务
- ETF/基金和股票池推荐是否查询或使用了产品/标的适配所需数据，如规模、流动性、费率、跟踪指数、波动、回撤、估值、资金、持仓风格、同类比较
- 若链路获取了 KYC 或市场证据，最终答案是否真实使用；查到但不用，仍要扣分

常见失败模式：
- 对 05 类问题没有任何获取或使用 KYC 数据的动作，却直接生成个人投资建议
- 明确需要数据比较却没有查数据
- 查了大量数据但没有服务于 KYC 适配和推荐取舍
- 工具输入过宽或过窄，导致结果无法支持最终建议
- 误读工具输出，或最终答案与工具结果冲突
- 耗时很长但质量提升有限
- 已有用户画像可用却没有读取，最终答案还以“未提供风险偏好”为前提

## 适用性判断

- **始终 relevant**，在链路诊断阶段评分。
