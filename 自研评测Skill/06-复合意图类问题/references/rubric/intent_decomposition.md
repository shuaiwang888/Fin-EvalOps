# `intent_decomposition` 意图拆解

判断模型是否识别用户一句话中的多个子任务、时间窗口、对象和输出要求。

关注点：
- 是否拆出所有关键子任务，而不是只回答最显眼的一问
- 是否识别子任务之间的依赖关系，例如先取数、再评估影响、再给策略
- 是否识别时间窗口，如 48 小时、7 天、事件后 1/3/5/10 日、3 月内最高到最低
- 是否识别对象范围，如多个行业、多个厂商、产业链环节、A 股映射、合约结构
- 是否保留用户原始问题中的量化、比较、案例和操作要求

常见失败模式：
- 只回答背景，不拆后续策略或影响评估
- 漏掉“有没有先例”“利润贡献多少”“估值是多少”等后半段要求
- 把多个强子任务合并成一个泛化主题
- 忽略关键时间窗口或比较对象

## 与 `task_coverage_priority` 的边界

`intent_decomposition` 关注模型是否在规划阶段识别出所有子任务；`task_coverage_priority` 关注最终答案是否真正覆盖并展开这些子任务。若模型未识别子任务导致答案遗漏，主要归因于 `intent_decomposition`；若模型识别了但答案未展开，主要归因于 `task_coverage_priority`。

## 适用性判断

- **始终 relevant**。
