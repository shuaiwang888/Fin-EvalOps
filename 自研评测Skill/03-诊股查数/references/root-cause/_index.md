# 根因归因体系

L1 分类固定不变，用于跨评测聚合统计。L2 是可执行的具体诊断。

## 链路阶段

| L1 | 链路阶段 | 核心问题 | 文件 |
|---|---|---|---|
| `intent` | 理解问题 | 是否识别用户真实诊股/查数意图和隐含金融语义？ | [intent.md](intent.md) |
| `evidence` | 检索数据/证据 | 是否找到正确、完整、及时、足够深的数据？ | [evidence.md](evidence.md) |
| `tool` | 选择与执行工具 | 是否选对工具、用对参数、处理工具约束？ | [tool.md](tool.md) |
| `reasoning` | 计算和金融推理 | 是否正确计算、换算、对比并使用市场框架？ | [reasoning.md](reasoning.md) |
| `composition` | 组织答案 | 是否把数据和推理表达成用户可用答案？ | [composition.md](composition.md) |

## 证据规则

每个根因必须绑定证据。证据可来自问题、最终答案、上下文、规划、工具调用、工具输出、耗时或线上信号。

## 置信度规则

- `high`：直接被可见答案或链路证据支撑。
- `medium`：强烈暗示但不完全明确。
- `low`：合理但证据不足；仅在宽泛分类仍有帮助时使用。

## 选择规则

1. 按 raw_score 升序排列活跃维度；并列时按动态权重降序，再按维度名字母序。
2. 如果触发封顶规则且封顶上限较低，封顶违规维度驱动主要根因。
3. 写一句 summary，将 L2 机制与该维度失败模式融合。
4. 按排名继续扫描，有独立病因则追加根因。
5. 最多返回 8 个根因。所有活跃维度 raw_score >= 60 且无封顶触发时允许返回空数组，否则至少一个根因。
